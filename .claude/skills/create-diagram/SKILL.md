# draw.io 図作成ワークフロー（汎用）

## 概要

ユーザーから指定された入力情報を元に、図種別に従って draw.io（XML）を生成する。
**最優先**: 読み手が誤解しない / 意思決定・実装・テストに落とせる。

---

## 入力（必須ヒアリング項目）

| 項目                  | 必須 | 説明・例                                         |
| --------------------- | :--: | ------------------------------------------------ |
| プロジェクト名        |  ✅  | タスク管理アプリ                                 |
| 入力情報              |  ✅  | 仕様書、議事録、要件、設計、手順など             |
| **図種別**            |  ✅  | 下記から選択                                     |
| **対象範囲（Scope）** |  ✅  | 「タスクCRUDのみ」「全体俯瞰」等                 |
| 抽象度                |  ⬜  | L1=俯瞰 / L2=主要詳細 / L3=実装寄り              |
| 前提/制約             |  ⬜  | 「外部連携はGoogleのみ」等                       |
| 入力ソース種別        |  ⬜  | 仕様書/議事録/ヒアリングメモ等（不確実性の目安） |

## 図種別一覧

| 種別ID                   | 説明                  | ユースケース               |
| ------------------------ | --------------------- | -------------------------- |
| `flow_swimlane`          | 業務フロー/承認フロー | 業務プロセス可視化         |
| `flow_transition`        | 画面遷移/状態遷移     | UI設計、状態管理           |
| `structure_architecture` | システム構成/全体構成 | インフラ設計、技術スタック |
| `data_er`                | ER図                  | DB設計                     |
| `behavior_sequence`      | シーケンス図（簡易）  | API設計、処理順序          |
| `org_structure`          | 体制図/役割           | プロジェクト体制           |
| `pipeline_cicd`          | CI/CDパイプライン     | DevOps設計                 |

## 出力（既定の割り振り）

> ⚠️ **図は「1ファイル=1図種別」（混在禁止）**
>
> ⚠️ **図のバージョニングを必須化（ファイル名に付与）**
>
> ⚠️ **図のスケール制限を超える場合は分割提案を優先**

### 図種別 → 出力先

| 図種別                   | 出力先                                       |
| ------------------------ | -------------------------------------------- |
| `flow_swimlane`          | `02_計画・要件定義/02.業務分析/`             |
| `flow_transition`        | `02_計画・要件定義/05.機能要件・非機能要件/` |
| `org_structure`          | `02_計画・要件定義/01.プロジェクト計画書/`   |
| `structure_architecture` | `03_設計・開発/01.基本設計/`                 |
| `data_er`                | `03_設計・開発/01.基本設計/`                 |
| `behavior_sequence`      | `03_設計・開発/02.詳細設計/`                 |
| `pipeline_cicd`          | `03_設計・開発/03.環境構築/`                 |

### ファイル名（バージョニング必須）

`[プロジェクト名]_[図種別]_[Scope]_v{MAJOR}.{MINOR}.drawio`

- 初版は `v1.0`
- 構造/境界/分割などが変わる変更: **MAJOR +1**（例 v2.0）
- 文言/注記/表記修正: **MINOR +1**（例 v1.1）
- 既存ファイルがある場合: **上書きせず必ずバージョンを繰り上げて保存**

### Mermaid変換オプション

**デフォルト出力**: draw.io（.drawio）

**Mermaid版が必要な場合**:

- ユーザーから「Mermaidでも出力して」と依頼された場合
- または既存の `.drawio` を読み込んで Mermaid に変換する場合

**Mermaid出力ファイル名**: `[プロジェクト名]_[図種別]_[Scope]_v{MAJOR}.{MINOR}.md`

**Mermaid対応図種別**:
| 図種別 | Mermaid対応 | 備考 |
|--------|:-----------:|------|
| `behavior_sequence` | ✅ | sequenceDiagram |
| `flow_swimlane` | △ | flowchart（レーン表現は限定的） |
| `data_er` | ✅ | erDiagram |
| `flow_transition` | ✅ | stateDiagram-v2 |
| `structure_architecture` | △ | flowchart（複雑なレイアウトは不向き） |
| `org_structure` | △ | flowchart TB |
| `pipeline_cicd` | ✅ | flowchart LR |

> 💡 **シーケンス図・ER図はMermaid向き**。構成図・業務フローはdraw.io推奨。

## 共通作法

### 必須要素

1. **タイトル**（上部中央）
2. **凡例**（下部）：色の意味は**図種別ごと**に定義
3. **注記**：Scope / 前提 / 仮定 / 対象外 を明示

### 品質基準

- **誤解防止**: 「描かないもの」を注記で明示
- **ID重複禁止**: 図種別ごとに Prefix を固定（下記）
- **グリッド整列**: ボックスが枠からはみ出さない、線が交差しすぎない
- **ラベル配置**: プロトコルラベル（HTTPS/SQL/OAuth2.0/SMTP等）は**該当エッジの中央**に配置

### 点線/破線の意味（図種別ごとに固定）

| 図種別                   | 点線/破線の意味                 |
| ------------------------ | ------------------------------- |
| `flow_swimlane`          | ループ（戻り）                  |
| `behavior_sequence`      | 非同期メッセージ、戻り（任意）  |
| `structure_architecture` | **配信（External→Client）専用** |
| `org_structure`          | 兼務                            |
| `flow_transition`        | 戻り遷移（Back/Cancel）         |

> ⚠️ **点線/破線は図内で混用しない。凡例に必ず意味を明記する。**

### 抽象度（L1/L2/L3）の定義

| 図種別                   | L1（俯瞰）                  | L2（主要詳細）              | L3（実装寄り）                        |
| ------------------------ | --------------------------- | --------------------------- | ------------------------------------- |
| `flow_swimlane`          | 主要ステップのみ            | 画面/処理単位               | API/DB操作粒度                        |
| `structure_architecture` | 主要コンポーネント+外部連携 | Queue/Cache/Worker/監視追加 | サブネット/冗長/認証方式/デプロイ単位 |
| `data_er`                | 主要エンティティのみ        | 全属性+FK                   | インデックス/制約/トリガー            |
| `behavior_sequence`      | 主要参加者+メッセージ       | 戻り+条件分岐               | ヘッダ/ペイロード/エラーハンドリング  |
| `flow_transition`        | 主要画面のみ                | 全画面+戻り                 | モーダル/ダイアログ/エラー状態        |

> 💡 **入力時に抽象度が指定されない場合は L1 をデフォルトとする**

### 図のスケール制限（必須）

- **1枚あたり上限**: ノード最大 **40**、エッジ最大 **60**
- 上限を超える場合:
  - そのまま作図せず、**分割案（粒度と枚数）を提示**してから作図
  - 分割は「自然な境界」で行う:

| 図種別                   | 分割の境界例                                      |
| ------------------------ | ------------------------------------------------- |
| `flow_swimlane`          | ユースケース単位 / フェーズ単位 / レーン単位      |
| `flow_transition`        | 主要画面群ごと（オンボーディング、ホーム、設定…） |
| `structure_architecture` | 領域ごと（Client、App、Data、External…）          |
| `data_er`                | ドメインごと（User系、Task系、Billing系…）        |
| `behavior_sequence`      | ユースケース単位（ログイン、作成、通知…）         |
| `org_structure`          | 部署/役割グループ単位                             |
| `pipeline_cicd`          | 環境別（dev/stg/prod）または stage別              |

## 図レシピ（図種別に応じて1つだけ適用）

---

### Recipe: `flow_swimlane`（業務フロー）

**抽出対象**

- アクター/システム → レーン
- ステップ → ボックス
- ループ → 点線矢印（戻り）

**レイアウト**

- 上→下、1行=1ステップ
- レーン: ユーザー/フロント/バック/DB/外部/非同期（必要なものだけ）

**ルール**

- DBは**操作で統一**（SELECT/INSERT/UPDATE/DELETE）
  - ❌ データ実体名（例：ユーザー情報データ）を箱にしない
  - ⭕ 操作名（例：User INSERT、Task UPDATE）
- **反復利用の機能は直線で終わらせない**（戻り矢印 or サブフロー分割）

**認証/OAuthの因果関係（典型形）**

```
フロント → 外部（認可） → バックエンド（コード交換/検証） → DB（保存） → フロント（ログイン状態）
```

**通知の因果関係（典型形）**

```
設定保存（DB） → スケジューラ起動（時刻到来） → 外部Push → ユーザー通知
```

※ 設定保存と送信を分ける（INSERT直後に通知が飛ぶように見せない）

**色分け**

| 種別         | 塗り      | 枠        |
| ------------ | --------- | --------- |
| 業務プロセス | `#FFF8E1` | `#FFB300` |
| システム処理 | `#E3F2FD` | `#1E88E5` |
| システム連携 | `#E8F5E9` | `#43A047` |
| データ操作   | `#F3E5F5` | `#8E24AA` |

**ID体系**

| Prefix | 用途                           |
| ------ | ------------------------------ |
| P-XXX  | プロセス（業務/システム処理）  |
| X-XXX  | 外部連携（OAuth/Push/SMS等）   |
| D-XXX  | データ操作（DBのCRUD）         |
| Q-XXX  | 非同期（キュー/スケジューラ）  |
| N-XXX  | 通知（ユーザーに到達する行為） |

**凡例（例）**: 業務/ユーザー操作、アプリ処理、外部連携、DB操作、非同期、通知

---

### Recipe: `structure_architecture`（システム構成）

**抽出対象**

- コンポーネント（App/DB/Cache/Queue等）
- 境界（Cloud/VPC/Subnet/On-prem等）
- 接続（API/DB/Queue）

**レイアウト**

- 層: Client → App → Data → External
- 領域: 境界線で Cloud / External / On-prem を分離

**ルール**

- エッジにプロトコル/方向（HTTPS/gRPC/SMTP等）を付与（分かる範囲で）
- 不明な点は「不明」と注記で明示

**追加ルール（必須）**

1. **因果関係（矢印の出発点）制約**
   - External Services への矢印は必ず **App Layer**（Backend/認証/連携/通知等）から出す
   - **Data Layer（RDB/Cache/Queue/Storage）から External へ直接矢印を出してはいけない**
   - Data Layer は App Layer から参照される側として表現する（SQL/Read/Write）
   - **External API呼び出しは「連携サービス（App Layer）」からのみ。Cache/Queue/Storageから外部への矢印は禁止**

2. **Push/非同期の表現固定**
   - Backend/Worker → Push通知サービス(APNs/FCM)：**実線**（HTTPS）
   - Push通知サービス(APNs/FCM) → Client(モバイルアプリ)：**破線**（Push）。**矢印頭必須**
   - 破線は「外部サービスからクライアントへの配信」以外に使わない

3. **OAuth の表現固定**
   - 認証サービス ↔ OAuth Provider：OAuth2.0（実線）
   - 認証サービス ↔ RDB：ユーザー/連携情報/トークン保存（SQL）
   - **RDB → OAuth Provider の矢印は禁止**

4. **ラベル配置**
   - プロトコルラベル（HTTPS/SQL/OAuth2.0/SMTP）は**該当エッジの中央に配置**
   - 他の線に紛れない位置に調整する
   - L1俯瞰では省略可（Redis→ラベルなし、Queue→Enqueue/Dequeue等）

5. **変更点注記**
   - バージョン更新時は図の下部に「vX.X 変更点: ...」を記載

**ID体系**
| Prefix | 用途 |
|--------|------|
| C-XXX | コンポーネント |
| B-XXX | 境界 |
| L-XXX | リンク（接続） |

**凡例（例）**: Client層 / App層 / Data層 / External / 境界

---

### Recipe: `data_er`（ER図）

**抽出対象**

- エンティティ
- 属性（PK/FK明示）
- 関係（1..N等）

**レイアウト**

- エンティティ: 箱に属性リスト
- 関係線: カーディナリティを明記

**ルール**

- 同名揺れを正規化（User/Users → User）
- 中間テーブルを明示（多対多の解消）

**ID体系**
| Prefix | 用途 |
|--------|------|
| E-XXX | エンティティ |
| R-XXX | リレーション |

**凡例（例）**: PK / FK / 1..N / N..N（中間）

---

### Recipe: `behavior_sequence`（シーケンス図：簡易）

**抽出対象**

- 参加者（ライフライン）
- メッセージ（同期/非同期）
- 順序

**レイアウト（簡易表現を固定）**

- 参加者 = 上部の箱 + 縦線（ライフライン）
- メッセージ = 水平矢印（同期は実線、非同期は点線）
- 戻り = 点線矢印（任意）
- **活性区間は原則省略**（描かない）

**ルール**

- メッセージ名: 「動詞＋目的語」
- 不明なメッセージは作らず、注記で未確定とする

**ID体系**
| Prefix | 用途 |
|--------|------|
| A-XXX | 参加者 |
| M-XXX | メッセージ |

**凡例（例）**: 同期 / 非同期 / 戻り（任意）

---

### Recipe: `flow_transition`（画面遷移/状態遷移）

**抽出対象**

- 画面/状態
- 遷移イベント
- 条件（分かる範囲で）

**レイアウト**

- 放射 または 左→右（規模に応じて選択）

**ルール**

- **戻り遷移（Back/Cancel）を落とさない**
- 初期状態/終了状態を明示

**ID体系**
| Prefix | 用途 |
|--------|------|
| SC-XXX | 画面/状態 |
| TR-XXX | 遷移 |

**凡例（例）**: 画面/状態 / 遷移 / 条件

---

### Recipe: `org_structure`（体制図/役割）

**抽出対象**

- 役割/担当
- 報告線
- 承認線（必要なら）

**レイアウト**

- ツリー構造

**ルール**

- 承認フローが複雑なら flow_swimlane に分離可
- 兼務は点線

**ID体系**
| Prefix | 用途 |
|--------|------|
| RL-XXX | 役割 |
| PS-XXX | 人 |

**凡例（例）**: 報告線 / 承認線 / 兼務

---

### Recipe: `pipeline_cicd`（CI/CD）

**抽出対象**

- Source/Build/Test/Deploy/Runtime/Observability
- 環境（dev/stg/prod）

**レイアウト**

- 左→右の直列
- 環境で段を分ける

**ルール**

- ツール名を明記（GitHub Actions/ArgoCD等）
- 承認ゲートを明示（手動承認/レビュー）

**ID体系**
| Prefix | 用途 |
|--------|------|
| J-XXX | ジョブ/ステップ |
| ENV-XXX | 環境 |
| G-XXX | ゲート |

**凡例（例）**: Stage / Environment / Gate

## draw.io XMLルール（共通）

### ボックススタイル

```
rounded=1;arcSize=10;whiteSpace=wrap;html=1;strokeWidth=1.5;fontSize=10;fontColor=#333333;
```

### エッジスタイル

```
edgeStyle=orthogonalEdgeStyle;rounded=0;orthogonalLoop=1;jettySize=auto;html=1;strokeColor=#757575;strokeWidth=1.5;endArrow=block;endFill=1;
```

### レイヤー順序

1. ヘッダー/境界
2. レーン背景（該当する場合）
3. エッジ（矢印）
4. ボックス
5. 凡例/注記

## セルフチェック（共通）

- [ ] Scopeが明示され、全体図に見える誤解がない

- [ ] ID重複なし
- [ ] 文字が枠内に収まる/はみ出しなし
- [ ] 図種別のレシピに沿っている（抽出対象・配置・表記）
- [ ] 凡例が配置されている
- [ ] 出力先が図種別の既定フォルダになっている
- [ ] **ノード数<=40、エッジ数<=60（超える場合は分割提案を行った）**
- [ ] **ファイル名に `_v{MAJOR}.{MINOR}` が付与されている**
- [ ] **バージョン更新ルールに沿って繰り上げている（上書き禁止）**
