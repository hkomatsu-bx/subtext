# draw.io 業務フロー系ワークフロー（WF-D-Flow）v2.0

## 対象図種別

| ID                  | 説明                        |
| ------------------- | --------------------------- |
| `biz_flow_swimlane` | ③ 業務フロー（As-Is/To-Be） |
| `biz_gap_analysis`  | ④ ギャップ分析              |

## 前処理（必須）

1. **図種別ID**を確定
2. **Scope**を確定（対象/対象外を2〜5行で明文化）
3. **As-Is / To-Be** を確定（業務フローの場合）
4. **抽象度**（L1/L2/L3）を確定（未指定はL1）
5. **レーン（列）数**を概算（5列推奨：ユーザー/フロント/外部/バック/DB、多くても7列まで）
6. **ノード/エッジ数**を概算（上限：40ノード/60エッジ）
   - 上限超えそうなら **作図せず、先に 分割案（境界/枚数/粒度） を提示**

## 抽出ルール

| 抽出対象 | 形状               | 説明                         |
| -------- | ------------------ | ---------------------------- |
| レーン   | スイムレーン（列） | 役割/部署（必要最小限）      |
| 処理     | 角丸長方形         | 1ノード=1アクション          |
| 分岐     | ひし形             | 条件分岐（条件文を短く明記） |
| 入出力   | ラベル/アイコン    | メール/帳票/ファイル/データ  |

> **Note**: Yes/No は可能なら OK/NG、あり/なしなどの短い条件語にする（視認性が上がる）。

## レイアウトルール（コンサル品質の固定型）

### レーン（列）配置（デフォルト）

- **縦レーン（列）**で固定（横レーン運用は禁止）
- 推奨列：ユーザー / アプリ（フロント） / 外部サービス / バックエンド / DB / 完了（任意）

### 時系列（読み順）

- **上→下**に時系列を積む（主幹フローは一直線）
- 横移動は「同一タイミングの連携」だけ（横移動を増やさない）

### 配置の原則（必須）

1. **主幹フロー（正常系）を中央寄せで一直線に通す**（蛇行禁止）
2. **例外/エラー/差戻しは右側に寄せる**（主幹フローを邪魔しない）
3. **外部連携/DB操作は 呼び出し元と同じ高さに置く**（外周配線禁止）
4. 合流が必要なら **合流点（小円 or 合流ノード）**を置く（線の束ね禁止）
5. **完了（終端）**はユーザーが完了を認識する最終ステップの直後に置く
6. 完了ノードへの矢印は **1本のみ**
7. **レスポンス表現**: 原則 **矢印ラベル** で表現し、ノード化しない（例：成功/失敗、400/404等は線の上に書く）

## draw.io固定ルール

- **XML形式**で出力
- **余白確保**: キャンバス上下左右40px以上、重なり禁止
- **whiteSpace=wrap**: 文字は枠内に収める
- **グリッド**: 10px、スナップON
- **サイズ統一**: 同種ノードは同サイズ（目安 W180px/H56px）

### エッジ（矢印）規格（必須）

- **コネクタ**: 直交（orthogonal）で統一
- **線幅**: 1.5pt固定
- **線の色**: 原則グレー固定（線で色分けしない。色はノードで表現）
- **ラベル位置**: 矢印中央（重なる場合は線ではなく配置を直す）
- **Y字分岐禁止**: 分岐は必ずひし形から2本出す（途中枝分かれ禁止）
- **外周配線禁止**: レーン境界に沿った大回りは禁止（ノードを寄せて最短化）
- **交差上限**: 交差が3本超えたら
  ①ノード再配置 → ②合流点追加 → ③分割提案

### 線種ルール

| 線種             | 用途                                  |
| ---------------- | ------------------------------------- |
| 実線（1.5pt）    | 通常フロー                            |
| 点線（dashed=1） | 戻り/ループのみ（例外表現に乱用禁止） |

### 分岐ラベル（Yes/No）配置ルール（必須）

1. ラベルは「ひし形から出る矢印」に付与する（処理ノードから直接Yes/Noは禁止）
2. 基本は矢印中央だが、**線に被る場合は 線から6〜10pxオフセットする**
   - **Yes**：矢印の上側へオフセット
   - **No**：矢印の右側へオフセット
3. それでも被る場合は、**ラベルの置き場を作る**
   - ひし形と接続先ノードの距離を **8〜16px 広げる**（ひし形/接続先どちらを動かしてもよい）
4. **どうしても解消できない場合の最終手段**：
   - 矢印ラベルを削除し、**テキストオブジェクト**で線の近くに配置（背景白推奨）

## ギャップ分析（④）追加ルール

### レイアウト

- **キャンバス左右分割**: 左As-Is / 右To-Be
- **対応関係**: 同一粒度で揃える（左右で粒度が違うのは禁止）
- 両側とも主幹フローは **縦レーン×上→下**で整える

### ギャップ表現

- **Callout（吹き出し）**: 差分箇所に配置
- **記述**: 「何が変わるか」を**一文で断定**
- **禁止**: "原因"と"対策"を混ぜない（分ける）

### 色ルール（追加）

| 種別             | 塗り      | 枠        | 用途   |
| ---------------- | --------- | --------- | ------ |
| As-Is 背景       | `#FAFAFA` | `#BDBDBD` | 左側   |
| To-Be 背景       | `#F1F8E9` | `#AED581` | 右側   |
| ギャップ吹き出し | `#FFF3E0` | `#FB8C00` | 変更点 |
| 高リスクギャップ | `#FFEBEE` | `#D32F2F` | 重大   |

## 抽象度ガイド

| レベル | 内容                                 |
| ------ | ------------------------------------ |
| L1     | 主要ステップのみ（10〜20ノード目安） |
| L2     | 画面/処理単位（20〜30ノード目安）    |
| L3     | API/DB操作粒度（分割必須）           |

### 分割境界

1. ユースケース単位
2. フェーズ単位
3. レーン単位
4. 例外が多い場合：例外だけ別図に分割

## セルフチェック

### 基本チェック

- [ ] **レーンは縦レーン（列）である**（横レーン禁止）
- [ ] 主幹フローが**上→下に一直線**（蛇行なし）
- [ ] 外部/DBが呼び出し元と同じ高さ（外周配線なし）
- [ ] 交差線が最小（3本超なら分割提案）
- [ ] 分岐ラベルが線に被っていない（オフセット/距離調整/テキストで解決）
- [ ] 完了ノードへの矢印は1本で、UIの最後に置かれている
- [ ] レスポンス（成功/失敗）がノードではなく**矢印ラベル**になっている
- [ ] As-Is/To-Beがタイトルに明記

### ギャップ分析チェック

- [ ] 左右で対応関係が読める（同一粒度）
- [ ] ギャップが観測可能な差分になっている
- [ ] Calloutが原因と対策を混ぜていない

### コンサル品質チェック

- [ ] **3秒で結論**（何のフローで何が分かる）が伝わる
- [ ] 読む順番が自然（上→下、例外は右側）
- [ ] 同種ノードのサイズが揃っている（W180/H56）
- [ ] 線が主張しすぎない（線グレー、色はノード）
- [ ] "対象外"が明記され、誤解余地が潰れている
- [ ] 図の主張が1つに絞られている
