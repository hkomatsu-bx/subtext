`subtext-meeting` スキルのステップ4（Slack 投稿）。

これは **Claude が実行する**段。ただし外部公開のため、**宛先チャンネルと親メッセージ案を提示し、
ユーザーの承認を得てから**投稿する。

手順:
1. セッションを解決し `data/out/<session>/minutes.md` を読む。
   - `$ARGUMENTS` にセッションがなければ `data/out/` の最新を提案しユーザー確認。
   - `minutes.md` が無ければ「先に `/subtext-minutes` を完了してください」と案内して止まる。
2. 投稿先チャンネルを確定する（**実行時に毎回指定**）:
   - `$ARGUMENTS` に `#channel` 指定があればそれ。無ければユーザーに尋ねる。
   - `slack_search_channels` で実在を確認し、チャンネル ID を得る。
3. **親メッセージ（要約）**を組み立てる。minutes.md から以下を簡潔に抽出:
   - 会議名 / 日時 / 出席者
   - 決定事項
   - ToDo（担当・期限が分かれば併記）
4. 投稿前に「投稿先チャンネル」と「親メッセージ案」を提示し、**承認を求める**。
5. 承認後:
   - `slack_send_message` で親メッセージ（要約）を投稿し、`thread_ts` を取得。
   - 同じスレッドに `minutes.md` 全文を返信する。**決定事項・ToDo は親メッセージに全文相当を
     出しているため、この2セクションはスレッドから除いて重複を避ける**（除いた場合はスレッド冒頭に
     「決定事項・ToDo は上の要約メッセージをご覧ください」の一文を添える）。Slack の文字数上限を
     超える場合は見出し境界で分割し、複数返信に分ける。
6. 投稿後、メッセージの permalink（取得できれば）と投稿件数を報告する。

**Slack 書式変換（重要）**: `minutes.md` は標準 Markdown（GFM）で書かれているが、Slack はこれを解釈しない。
親メッセージ・スレッド返信のどちらも、送信前に次のルールで手作業で変換すること（`meeting slack` の
`to_mrkdwn` と同じ変換ルール。`##`/`###` 見出しや `**`/`- ` をそのまま送らない）:

- 見出し `## X` / `### X` → `*X*`（単一アスタリスクの太字。Slack に見出し記法は無い）。**見出しの前には
  必ず空行を1行入れる**（元の Markdown で省かれていても入れる。セクション同士が詰まって見えないように
  するため）。
- 太字 `**X**` → `*X*`（Slack は二重アスタリスクを太字と解釈せず、記号がそのまま表示される）
- 箇条書き `- X` / `* X` → `• X`
- チェックボックス（未完了）`- [ ] X` → `☐ X`、（完了）`- [x] X` → `☑ X`。ToDo の担当・期限・完了条件は
  1行にまとめず、チェックボックスの下に1段インデントした `    • ` で残す。ToDo項目同士の間にも空行を
  1行入れる（1行に詰まっていると見落とされるため）。
- 水平線 `---` → 空行
- 番号付きリストが必要な場合は `1. 2. 3.` をそのまま使ってよい（Slack はこれを地の文として表示するため、
  そのままでも番号付きリストらしく見える）
- コードブロック（\`\`\` で囲まれた範囲）は変換せずそのまま残す

注意: 音声・PII を含む内容を外部へ出す操作。チャンネルの取り違えがないか必ず確認すること。
