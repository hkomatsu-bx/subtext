Web 会議の音声・字幕から、Subtext を使って議事録（minutes.md）を作り、Slack へ投稿するまでの手順書です。 運用担当者（エンジニアでなくても回せること）を想定しています。

通常の運用は画面（TUI）だけで一周できます。 録音・取込・話者名の記入・議事録・Slack 投稿は、すべて1つの画面の中で完結します。

初めての人は「0. まず手元にあるものを確認する」→「1. 事前準備」→「2. 画面で進める（TUI）」の順に読んでください。 画面では届かない細かい操作（ライブ字幕、セッションや月を指定した実行、--no-summarize での課金ゼロ運用）は「5. コマンドで細かく操作する（CLI）」にあります。

用語ミニ辞典（先に4つだけ）

用語 かんたんな意味
セッション 1回の会議に対応する作業フォルダ。data/recordings/20260704-140000/ のように日時が名前になる。
文字起こし（Transcribe） 音声を AWS のサービスで文字にする処理。AWS 課金が発生。
要約（Bedrock / Claude） 文字起こしから議事録の体裁（決定事項・ToDo 等）を作る処理。
話者名ゲート 「spk_0 は誰？」を人間が埋めるまで議事録を作らせない安全弁。必ず1回止まる。

0. まず手元にあるものを確認する

議事録の入口は 3通り あります。 手元にあるものと、AWS 課金の許容度で選んでください。 3通りとも画面（TUI）から実行できます。

経路 手元にあるもの AWS 課金 主な用途
A. 録音経路 これから会議する（音声を録りたい） 文字起こし＋要約 会議に参加せず、自分の PC の音声から録る主経路
B. WebVTT 直接 Teams 等が出した字幕ファイル（.vtt） 要約のみ 既に字幕がある。最も安く速い
C. 録画 mp4 会議の録画（.mp4） 文字起こし＋要約 録画しか残っていない
  • 迷ったら：字幕(.vtt)があれば B、録画(.mp4)しかなければ C、これから録るなら A。
  • B と C は最終的に同じ「VTT を投入して議事録化」に合流します（C は mp4 から VTT を作ってから B と同じ流れ）。
  • このほかに、会議中にライブ字幕を流しておいた場合はその記録からも議事録を作れます。会議中の確認が主目的の機能なので、通常は A〜C から選んでください（手順は §5-6）。
入口は次のどれか1つ（A / B / C いずれも「話者名の確認」に必ず合流する）:

  A. 録音
  B. 字幕VTT
  C. 録画mp4 →（VTT に変換）
        ↓（A・B・C いずれも）
  話者名の確認（必ず1回停止）─→ 議事録 minutes.md ─→ Slack 投稿

1. 事前準備（初回・その PC で1回だけ）

開発担当から受け取った配布フォルダ（Subtext.sln があるフォルダ）を使えるようにします。 以降のコマンドはすべて、このフォルダを開いた状態で実行します。

1-1. uv と PowerShell 7 を入れる

この 2 つだけ先に入れます（社内 PC で導入できない場合は情シス／開発担当へ相談）。

winget install astral-sh.uv            # Python 環境管理。Python 本体は uv が用意します
winget install Microsoft.PowerShell    # PowerShell 7（pwsh）

PowerShell 7（pwsh）は Windows 標準の powershell.exe（5.1）とは別物です。 5.1 では動きません。導入後は pwsh と入力して開くウィンドウを使ってください。

1-2. 配布フォルダを置く

受け取った一式を、パスに空白や日本語を含まない場所（例：C:\Subtext）へ展開します。 中に Subtext.sln と dist フォルダがあることを確認してください。

dist には録音（dist\recorder）とライブ字幕（dist\live）の実行ファイルが入っています。 これがあるため、この PC に .NET SDK を入れる必要はありません。

「このシステムではスクリプトの実行が無効になっている」と出たら

zip やファイル共有で受け取ると、Windows が .ps1 に「別の PC から来たファイル」の印を付けて実行を止めます。次を1回流すと外れます。

Unblock-File -Path scripts\*.ps1

1-3. セットアップスクリプトを1回流す

pwsh -NoProfile -File scripts/bootstrap.ps1

これで Python 環境の用意、.env の雛形コピー、data/ フォルダ作成まで済みます。 uv が入っていないとここで停止します（1-1 に戻ってください）。

1-4. .env（設定ファイル）を埋める

配布フォルダの直下に .env が作られます。 最低限これだけ埋めてください（値は情報システム担当や CDK デプロイ結果から受け取る）。

項目 いつ必要 補足
S3_BUCKET 経路 A / C（文字起こしを使う時） 文字起こし用のバケット名
BEDROCK_MODEL_ID Bedrock で要約する時 東京リージョンで有効化済みのモデル ID
AWS_REGION 既定 ap-northeast-1 のままで可
SLACK_BOT_TOKEN Slack へ投稿する時 xoxb- で始まる Bot Token。bootstrap では作られないので手で追記する

重要（機密の扱い）

  • .env に AWS のパスワードやアクセスキーは書かない。AWS 認証は「AWS プロファイル / SSO」で通す（担当者に確認）。
  • .env はコミット（Git に登録）しない。会議の音声・実名などの個人情報は社外に出さない方針です。

Slack 投稿（§2-6）を使うなら：SLACK_BOT_TOKEN（xoxb- で始まる Bot Token）を手で追記します。これが無いと投稿だけが失敗します。Claude Code の Slack プラグインは使いません（Bot Token で直接投稿します）。

1-5.（経路 C を使う時のみ）ffmpeg を入れる

録画 mp4 から音声を抜くのに ffmpeg が必要です。 未導入なら以下（Windows・scoop 利用時）。

scoop install ffmpeg

入っているか確認：ffmpeg -version が表示されれば OK。 画面から mp4 を取り込むときは、長さの測定にも同梱の ffprobe を使います。

1-6. AWS にログインできているか（経路 A / C）

文字起こし・要約は AWS を使います。 会議の前に、AWS プロファイル/SSO でログイン済みか担当者に確認してください（未ログインだと途中で失敗します）。

最後に、本番前の動作確認を1回してください。 §2 の手順で1分だけ録音してみて、録音が始まることを確かめておきます。会議直前に起動しないと気づいても、その日の音声は取り返せません。

2. 画面で進める（TUI）

録音から Slack 投稿までを1つの画面で進めます。 通常の運用はこの章だけで足ります。

2-1. 起動する

配布フォルダで、通常のターミナルから：

uv run meeting tui

注意：Claude Code のセッション内からは起動しないでください。録音は WASAPI（Windows の音声層）を使うため、通常のターミナルで動かす必要があります。

2-2. 画面の見方

  • 一覧：セッション番号、セッション名、今どの段か、録音状態、録音長（self / others の秒数）。取込由来のセッションは録音長が - になります。
  • 上部の帯：01 録音 → 02 取込 → 03 議事録 → 04 共有 の4段。選択中のセッションが今どこにいるかを示します。
  • 右上のコスト：今月 $x.xx / $y.yy（今月の累計と月次上限）。
  • ログ：実行中の見積・進捗・エラーがここに出ます。Ctrl+L で一覧を隠してログを広げられます。

キー操作（画面下部にも出ます）：

キー 操作
r 録音の開始／停止
i 取込（VTT / mp4）
m 議事録作成
s Slack 投稿
x セッション削除
Ctrl+R 一覧の再読込
Ctrl+L ログの拡大／縮小
Ctrl+P コマンドパレット（Claude 経路の切替に使う。§2-7）
q 終了

2-3. 録音する（経路 A）

会議が始まる前に、左端の入力欄に録音する分数を入れて（既定 180 分）、r（または「録音開始」）を押します。

  • 出力先：data/recordings/<日時>/（self.wav＝自分, others.wav＝相手, manifest.json など）。
  • 録音には dist\recorder の実行ファイルを使います。押しても録音が始まらない場合は §7 を見てください。
  • 会議が終わったら、もう一度 r（「停止」）を押します。指定した分数に達すると自動でも止まります。
  • 画面を閉じると、録音中なら自動で安全停止してから閉じます（消し忘れ防止）。15 秒待って止まらない場合は強制終了するため、manifest.json が不完全になることがあります。通常は r で止めてから終了してください。

2-4. 字幕・録画を取り込む（経路 B / C）

i（「取込 VTT/mp4」）を押し、ファイルのパスを入力します。 拡張子で自動的に振り分かれるので、.vtt と .mp4 のどちらでも同じ操作です。

  • Windows の「パスのコピー」で付く前後の " はそのまま貼って構いません（自動で外します）。
  • .mp4 の場合：ffprobe で長さを測り、文字起こしの概算コストをログに出してから変換に入ります。長さが測れない場合（ffmpeg 未導入、音声の無い mp4 など）は、課金される段に入る前に中止します。ログの案内に従って ffmpeg を入れてください。
  • .vtt の場合は文字起こしを使わないので、この段の AWS 課金はありません。
  • 取り込むと、そのまま話者名ゲート（§2-5）へ進みます。

取込セッションは画面を再起動すると続けられません。 画面は取り込んだファイルの場所を記憶に留めるだけで保存しないため、再起動後に議事録を作り直したい場合は「取込」から同じファイルを指定し直してください（mp4 の場合は、変換済みの .vtt を指定すれば文字起こしの再課金を避けられます）。

2-5. 議事録を作る

m（「議事録作成」）を押します。 録音経路（§2-3）の場合はここから、取込（§2-4）の場合は取込に続けて自動で進みます。

話者名の記入モーダルが開きます。 「spk_0 は誰か」を人間が確定させるための安全弁（話者名ゲート）で、必ず1回止まります。

  1. 話者ラベルごとに、発話数と代表的な発言がいくつか表示されます。
  2. それを手がかりに、実名や役割を入力します。誰か分からない話者は、分かる範囲（例：「進行役」「お客様A」）で構いません。
  3. 空欄にしたラベルは spk_0 などの表記のまま議事録に残ります。
  4. 「保存して続行」を押すと、そのまま議事録の生成まで自動で進みます。完了すると data/out/<セッション>/minutes.md ができます。
  • 実名と代表発言はモーダルの中だけに表示され、ログには記入件数しか出ません。
  • 中止した場合は議事録は作られません。m を押せば同じところから再開できます。
  • 自動で続きに進むのは1セッションにつき1回までです。2回目以降は m を押し直してください。
  • 記入した内容は data/out/<セッション>/speaker_names.json に保存されます。ファイルを直接編集したい場合は §3 を参照。

話者名の記入は手元のファイルを書くだけで、外部送信はありません。

2-6. Slack へ投稿する

minutes.md ができたセッションを選び、s（「Slack投稿」）を押します。

  1. 投稿プレビューと投稿先チャンネル ID の入力欄が出ます（meeting.toml に既定チャンネルがあれば入力済み）。
  2. 中身を確認して「投稿する」を押すと投稿します。Esc で中止。
  3. 投稿スタイルは、親メッセージ＝要約（日時タイトル・決定事項・主な ToDo）、スレッド返信＝minutes.md の全文（長い場合は分割）。
  • チャンネルはID（C で始まる文字列。チャンネル詳細の最下部で確認）で指定します。チャンネル名（#general など）では通りません。
  • この経路は Claude／Anthropic を経由しないため、議事録の中身が社外へ出ません。
  • SLACK_BOT_TOKEN が未設定だとここで失敗します（§1-4）。
  • 再投稿の注意：投稿の冪等性は実装していません。同じセッションで2回押すと、親メッセージと全文がもう一度投稿されます。

2-7. Claude 生成に切り替える

ボタンとキー操作は Bedrock 固定です。 議事録の文章化を Claude に任せたい場合は、Ctrl+P でコマンドパレットを開いて次を選びます（判断基準は §4）。

  • 議事録を生成 (Claude)
  • 取込 VTT/mp4 (Claude)

この経路は final_transcript.json を作った時点で正常終了し、minutes.md はできません。 続きの文章化の手順は §5-7 と同じです（ログにも同じ案内が出ます）。

2-8. 画面でできないこと

次の操作はコマンド（§5）で行います。

  • ライブ字幕の開始 → uv run meeting live（§5-6）
  • 課金ゼロで止める運用（--no-summarize）→ §5-2
  • 過去の月のコスト明細を見る → uv run meeting cost --month 2026-07（§6）
  • 議事録だけ作り直す（段を指定した再実行）→ §7 の表

なお、セッション削除（x）は録音フォルダと出力フォルダを消します。 コスト台帳（cost-ledger.jsonl）の記録は監査のため残ります。 確認画面で y を押すと削除され、取り消せません（n または Esc で中止）。

3.［共通］話者名の確認（話者名ゲート）

どの経路でも、議事録を作る前に必ず1回止まります。 これは「spk_0 は誰の発言か」を人間が確定させるための安全弁です。

画面（TUI）ではモーダルが開き、記入するとそのまま続きが走ります（§2-5）。 コマンド（CLI）で subtext-postmeeting を直接使った場合は、ファイルを自分で編集します。

  1. 止まると data/out/<セッション>/speaker_names.json が作られます。
  2. このファイルを開き、話者ラベル（spk_0, spk_1 …）に実名や役割を記入します。
    • 経路 B/C では VTT に入っていた名前が初期値として入っていることがあります。中身を確認・補正してください。
    • 誰か分からない話者は、分かる範囲（例：「進行役」「お客様A」）で構いません。
  3. 保存したら、直前に実行したコマンドを再実行します。今度はゲートを通過して minutes.md まで進みます。

話者名の記入そのものはローカルのファイル（speaker_names.json）を編集するだけで、外部送信はありません。 ただし割り当てを Claude Code に手伝ってもらう場合は、Claude が発言内容（実名入りトランスクリプト）を読むため Anthropic 側へ送信されます。Bedrock 経路を選んで PII を社外に出さない運用にしているなら、話者名は手作業で記入してください。

4. 要約バックエンドの選び方（Bedrock か Claude か）

議事録の「文章化」を誰にやらせるかで2通りあります。 どちらを使うかは情報の取り扱い方針で決めてください。

方式 画面での選び方 コマンド データの行き先 向いている場面
Bedrock（既定） m / i（ボタン） meeting minutes 文字起こしも要約も自社 AWS 内（日本国内）に留まる 個人情報を社外に出したくない通常運用
Claude 生成 Ctrl+P から選択（§2-7） meeting minutes --claude / --no-summarize 実名入りトランスクリプトが Anthropic 側へ送信される ガバナンス上問題ない、Claude の文章品質を使いたい時
  • 判断に迷う場合は既定（Bedrock）を選んでください。
  • Bedrock 経路は minutes.md まで自動で作られます。Claude 生成経路は final_transcript.json で止まるため、文章化のひと手間が別に必要です（§5-7）。
  • Claude 生成経路では用語補正（固有名詞の表記直し）が効きません。 課金をゼロにするために要約段と一緒に自動でスキップされるためです。社名・製品名・人名の表記を揃えたい場合は、Claude に文章化を頼むときに正しい表記の一覧も一緒に渡してください（tools/correction/terms.json の canonical がその一覧です）。表記の正確さを重視するなら Bedrock 経路を選ぶほうが確実です。
  • どちらの経路でも議事録の見出しは統一（## 決定事項 / ## ToDo / ## 論点・議論サマリ）。トランスクリプトに無い情報は創作されません。
  • （この表とデータの行き先の「正」は .claude/skills/subtext-meeting/SKILL.md ステップ3。ガバナンス変更時はそちらを先に更新する。）

5. コマンドで細かく操作する（CLI）

画面（§2）で足りる範囲はここを読む必要はありません。 セッションや段を明示して実行したい場合、課金をゼロに抑えたい場合、ライブ字幕を使う場合にここを見てください。

注意：これらのコマンドはあなた自身が普通のターミナルで実行します。特に録音とライブ字幕は Claude Code のセッション内からは起動できません。文字起こし・要約は AWS 課金を伴うため、ターミナルから実行して cost-ledger.jsonl に記録します。

5-1. 経路A：録音して議事録を作る

uv run meeting record 60     # 最大 60 分録る（省略時は 180 分）
uv run meeting stop          # 別のターミナルから停止
uv run meeting status        # 今どの段かをファイルの有無から判定
uv run meeting minutes       # 最新セッションを Bedrock で議事録まで
  • stop は停止の合図ファイルを置くだけの安全な操作です。録音側がこれを検知して安全に止まり、manifest.json を確定します。
  • セッションを指定する場合：uv run meeting minutes 20260704-140000
  • 実行時に「今回の概算コスト／今月の累計／上限」を表示し、cost-ledger.jsonl に記録します。上限超過は警告のみ（止まりません）。

▶ ここで話者名ゲートで1回止まります（「話者名の記入が必要です（BR-NAME-01）」と表示）。 話者名の確認を済ませたら、セッションを明示して再実行します（uv run meeting minutes <セッション>）。 引数を省くと最後に更新されたセッションが対象になります。 録音セッションだけでなく取込由来のセッション（Recording、live_captions など）も候補に入るため、待っている間に別の録音や取込があるとそちらへ向かいます。 uv run meeting status で確認したセッション名を渡すのが安全です。

5-2. 経路B：字幕（WebVTT）から議事録を作る

Teams 等が出力した字幕ファイル meeting.vtt が手元にある場合。 録音・文字起こしが不要で、いちばん安く速い経路です。

# 1回目：話者名ゲートで止まる（VTT 内の話者名が初期値として入る）
uv run subtext-postmeeting --mode vtt --vtt meeting.vtt

▶ 話者名ゲートで止まる → 話者名の確認へ。 名前を確認・補正したら 同じコマンドをもう一度実行 → minutes.md が完成します。

AWS 課金を完全にゼロにしたい場合は --no-summarize を付けます。 要約段だけでなく用語補正（C2）段も自動でスキップし、final_transcript.json まで作って止まります（Bedrock を一切呼ばないので BEDROCK_MODEL_ID も不要）。 議事録の文章化は Claude Code 側に任せられます（§5-7）。

uv run subtext-postmeeting --mode vtt --vtt meeting.vtt --no-summarize

5-3. 経路C：録画（mp4）から議事録を作る

会議の録画 recording.mp4 しか残っていない場合。 ffmpeg で音声を抜き、文字起こしして VTT を作り、経路 B に合流します。

# ffmpeg で音声抽出 → 文字起こし → recording.vtt を生成
uv run subtext-mp4-to-vtt recording.mp4

# あとは経路 B と同じ
uv run subtext-postmeeting --mode vtt --vtt recording.vtt
  • 事前に ffmpeg が必要（1-5）。
  • 変換ステップの AWS 課金は文字起こし（Transcribe）のみ（この後の議事録化で要約段の課金があり得ます）。抽出した音声は一時ファイルとして自動で消えます。
  • ▶ 話者名ゲート → 話者名の確認 → 同じコマンド再実行で minutes.md 完成。

5-4. 対話1コマンドでまとめて進める（process）

話者名の記入とファイル編集を自分でやらずに済ませたい場合は、minutes の代わりに process を使います。 画面（§2-5）の話者名モーダルに相当する流れを、ターミナルの対話で行います。

uv run meeting process              # 最新セッション。話者名を対話で聞き、そのまま議事録まで進む
uv run meeting process 20260704-140000 --channel C0123456789
  • 話者名ゲートで止まる代わりに、話者ごとの代表発言を見せながら名前を聞いてくれます。入力すると speaker_names.json に書き戻し、自動で続きを実行します。
  • 最後に Slack 投稿を提案します（--channel を省くと投稿先を対話で聞きます）。投稿するかどうかは必ず確認されます。

5-5. Slack へ投稿する

data/out/<セッション>/minutes.md が出来たら Slack へ共有します。

Slack 投稿は人間の承認が必須です。宛先チャンネルと投稿文を確認してから投稿します（自動投稿はしません）。

uv run meeting slack --channel C0123456789          # 最新セッション
uv run meeting slack 20260704-140000 --channel C0123456789

投稿前にプレビューが出て y/N を聞かれます。 y 以外なら投稿しません。 この経路は Claude／Anthropic を経由しないため、議事録の中身が社外（Anthropic）へ出ません。

  • --channel を省略すると meeting.toml の既定チャンネル、それも無ければ対話で聞きます。
  • meeting process（§5-4）を使った場合は、最後に投稿するかを聞かれるのでこの手順は不要です。
  • 投稿スタイルと再投稿の注意は §2-6 と同じです。

Claude Code に文面を作らせることもできます。 /subtext-slack を使うと、minutes.md を読んで投稿文案と宛先を提示 → あなたが承認 → 投稿 → 投稿リンクを報告、という流れになります。 文面を練りたい時に向きますが、議事録の内容が Anthropic 側へ送信される点は Claude 生成経路と同じです。

5-6. ライブ字幕の記録から議事録を作る

会議中にライブ字幕を流していた場合、その確定字幕から議事録を作れます。 録音（経路 A）の代わりにはなりますが、字幕確定までの遅延があるため精度は録音経路に劣ります。 この操作は画面（TUI）にはありません。

# 会議中: ライブ字幕を画面に出しつつ、確定字幕を記録する（このターミナルを占有します）
uv run meeting live

起動時にこのライブ字幕専用のセッション名と JSONL の場所が表示されるので、控えてください（録音セッションとは別に採番されます）。 会議が終わったら、そのターミナルで Ctrl+C を押して止めます。 終了時に、続きのコマンドがそのまま画面に出ます。

# 会議後: 記録した JSONL を VTT に変換する
uv run subtext-live-to-vtt data/out/<セッション>/live_captions.jsonl

# 以降は経路 B と同じ
uv run subtext-postmeeting --mode vtt --vtt data/out/<セッション>/live_captions.vtt
  • ライブ字幕は通常のターミナルで起動します（録音と同じ理由）。
  • uv run meeting stop では止まりません（あれは録音用）。別のターミナルから止めたい場合は data/out/<セッション>/.stop という空ファイルを作ります。
  • AWS 課金は、会議中に Transcribe のストリーミング分が発生します。会議後の議事録化で要約段の課金が追加されます（--no-summarize ならゼロ）。

5-7.（Claude 生成を選んだ場合）議事録の文章化

Claude 生成経路（画面の Ctrl+P メニュー、--claude、--no-summarize）は final_transcript.json を作った時点で正常終了します。 この時点では minutes.md はまだありません。

続けて Claude Code に data/out/<セッション>/final_transcript.json を読ませ、議事録の文章化を依頼してください（ログにも同じ案内が出ます）。 生成された内容を data/out/<セッション>/minutes.md として保存すれば、以降の Slack 投稿は Bedrock 経路と同じ手順になります。

このとき、トランスクリプトの固有名詞は補正されていません（用語補正が要約段と一緒にスキップされるため）。 依頼のときに正しい表記の一覧（tools/correction/terms.json の canonical）も渡すと、社名・製品名の表記ゆれを抑えられます。

6. コストと注意点

  • AWS 課金が出る操作：文字起こし（経路 A・C）、Bedrock 要約（既定）、用語補正（C2）段の Bedrock（既定で有効）。ただし --no-summarize を付けると要約段と補正段の両方が自動でスキップされるため、経路 B は --no-summarize で課金ゼロ。

  • 議事録の生成は、画面からでもコマンドからでも実行のたびに概算を tools/meeting/cost-ledger.jsonl に記録します。累計は画面の右上に出るほか、次で確認できます。

    uv run meeting cost              # 今月のサマリ
uv run meeting cost --month 2026-07

  • 表示額は概算です。正確な請求額は AWS Cost Explorer を確認してください。

  • 上限（既定：単発 $5 / 月次 $50。改定は tools/meeting/meeting.toml の [thresholds] で行う）を超えると警告が出ますが処理は止まりません。想定外に高い時は担当者へ。

  • mp4 の取込は、長さが測れない場合に課金される段へ入る前に中止します（§2-4）。

7. 困ったときは（トラブルシューティング）

症状 対処
話者名の記入モーダルが出た／「話者名の記入が必要です」で止まった 正常です（話者名ゲート）。画面なら記入して「保存して続行」（§2-5）、コマンドなら話者名の確認を済ませて再実行（経路 A はセッション名を明示）。
録音が起動直後に失敗する 普通のターミナルで実行していますか？ Claude Code セッション内からは録音できません。
画面を再起動したら取込セッションの議事録が作れない 取り込んだファイルの場所は保存されません。「取込」から同じファイル（mp4 は変換済みの .vtt）を指定し直してください（§2-4）。
mp4 取込が「長さを取得できませんでした」で止まる ffmpeg -version が通るか確認（1-5）。音声トラックの無い mp4 でも起きます。課金前に止めているので余分な請求はありません。
文字起こしで AWS エラー AWS にログイン済みか、.env の S3_BUCKET が入っているか確認。
要約で失敗（Bedrock） .env の BEDROCK_MODEL_ID が東京で有効なモデルか確認。
どのセッションか分からない 画面の一覧、または uv run meeting status で現在地を確認。録音は data/recordings/、議事録は data/out/ にある。
議事録だけ作り直したい（Bedrock 経路） 経路 A：uv run subtext-postmeeting --mode paired --session data/recordings/<セッション> --stage summarized／経路 B・C：uv run subtext-postmeeting --mode vtt --vtt <ファイル> --stage summarized
Slack 投稿だけ失敗する（SLACK_BOT_TOKEN が未設定です） ルート .env に SLACK_BOT_TOKEN（xoxb- で始まる値）を追記。.env.example から新規作成した場合は空欄なので手で入れる（§1-4）。
Slack 投稿で channel_not_found まずプライベートチャンネルなら Bot を招待してください（対象チャンネルで /invite @<Bot名>）。プライベートは参加していないと存在ごと隠されるため、このエラーになります。パブリックチャンネルは招待なしで投稿できる設定なので、そこで出る場合はチャンネルID（C で始まる文字列。チャンネル詳細の最下部で確認）が誤っています。チャンネル名（#general など）では通りません。
Claude 経路を選んだら minutes.md が出来ない 仕様です。Claude 生成経路は final_transcript.json で止まります（§5-7）。
話者名を直したのに議事録に反映されない 一度通過した実名割当は再利用されます。uv run subtext-postmeeting --mode paired --session data/recordings/<セッション> --stage named で割当からやり直してください。

付録：コマンド早見表

すべて配布フォルダで実行。

# --- 通常はこれ1つ（録音・取込・議事録・Slack を画面で。ライブ字幕を除く）---
uv run meeting tui

# --- 経路A：録音経路 ---
uv run meeting record 60          # 録音開始（分指定。省略時 180 分）
uv run meeting stop               # 録音停止
uv run meeting status             # 現在地の確認
uv run meeting minutes            # 議事録生成（Bedrock 要約, 既定）
uv run meeting minutes --claude   # 議事録生成（Claude 生成。final_transcript.json で停止）
uv run meeting process            # 話者名を対話で聞いて議事録→Slack まで
uv run meeting cost               # コスト月次サマリ

# --- Slack 投稿（生成済み議事録を投稿。プレビュー＋y/N 承認）---
uv run meeting slack --channel C0123456789

# --- 経路B：WebVTT 直接 ---
uv run subtext-postmeeting --mode vtt --vtt meeting.vtt                 # 議事録まで
uv run subtext-postmeeting --mode vtt --vtt meeting.vtt --no-summarize  # 要約は Claude に任せる

# --- 経路C：録画 mp4 → VTT ---
uv run subtext-mp4-to-vtt recording.mp4                                 # mp4→VTT
uv run subtext-postmeeting --mode vtt --vtt recording.vtt               # 以降は経路B と同じ

# --- ライブ字幕とその記録から議事録（画面にはない）---
uv run meeting live                                                     # 会議中（Ctrl+C で停止）
uv run subtext-live-to-vtt data/out/<セッション>/live_captions.jsonl     # JSONL→VTT
