# 付録：トレーサビリティ

ソースコードのコメントは、機能要件 `FR-xx`・非機能要件 `NFR-xx`／`NFR-SEC-xx`・業務ルール `BR-xxx-xx`・設計判断 `Qn=X` を識別子として参照する。
追加機能スライスでは、これらにスライス名を挟んだ `FR-A1-xx`・`NFR-C2-xx`・`BR-H2-AUTH-xx` の形も使う。
本付録はこれらの定義の一次情報である。
コードのコメントを読んでコードの意図を確認するときは、ここを引く。

読み方の注意を 3 つ挙げる。

- **BR-* はユニットごとに独立採番される**。`BR-IO-01`・`BR-ERR-01`・`BR-SEC-01` は Unit A・B・C でそれぞれ別の内容を指す。参照時はユニットを併記すること。
- **Qn=X はステージごとに独立採番される**。同じ `Q4=A` でも、ステージ（要件分析・Unit A 機能設計・Unit B 機能設計など）が違えば意味が異なる。
- **末尾の番号を省いた `FR-A1`・`FR-C2`・`BR-CORR` のような書き方は、そのスライスや規則群の全体を指す**。個別の条項ではない。

コードには本付録が扱わない別系統の識別子も現れる。
検証スパイク `SC-Pn`、実機で見つけた課題 `ISS-nn`、設計判断の細目 `DG-<スライス>-n`、受け入れ条件 `AC-<スライス>-nn` である。
このうち `DG-*` と `AC-*` で実装が参照するものは第 5 節に載せる。
`SC-Pn`（PoC の成功基準）と `ISS-nn`（実機検証で起票した課題）は第 6 節に載せる。

なお、本付録の全条項がコードから参照されるわけではない。
プロジェクト全体の方針（`NFR-01`〜`NFR-05` など）や、実装しないと決めたルール（`BR-QLT-01`）は文書側で完結する。
逆に、実装があってもコメントが条項を引いていない箇所もある（`BR-VTT-*`・`BR-CAP-*` など）。
参照の有無は実装の有無を意味しない。

## 1. 機能要件（FR）

出典は要件文書 §4。
優先度は P1（最優先・実現性の要）／P2／P3。

### 音声キャプチャ・録音

| コード | 優先度 | 内容 |
|--------|--------|------|
| FR-01 | P1 | システム出力（相手の声）を WASAPI ループバックで取得する。会議に参加せず取得する |
| FR-02 | P1 | マイク入力（自分の声）を別系統で取得する。これで「自分／相手」を確実に区別する |
| FR-03 | P1 | 2 系統をそれぞれ WAV としてタイムスタンプ付きで保存する（会議後処理の入力） |
| FR-04 | P1 | 2 系統の時間同期を取る。ループバックの無音欠落は、チャンク単位のタイムスタンプ付与または無音挿入で補正する |
| FR-05 | P2 | capture 層は既定形式で取得し、recorder 段で 16kHz・モノラル・16bit PCM に正規化する |
| FR-06 | P2 | 出力デバイスを選択できる。混入の程度と自分の声の二重取りの有無を検証できる |

### 会議後パイプライン

| コード | 優先度 | 内容 |
|--------|--------|------|
| FR-07 | P1 | 正規化済み WAV を S3 経由で Transcribe バッチに渡し、文字起こしと話者分離（最大 5）を実行する |
| FR-08 | P1 | 日本語の会議（相手 2〜5 名）で話者クラスタが分離される。PoC 最大の不確実性 |
| FR-09 | P3 | 話者クラスタへ実名を手動で割り当てる（声紋登録は対象外） |
| FR-10 | P3 | Bedrock（Claude）で、決定事項・ToDo（担当・期限）・論点を含む構造化 Markdown 議事録を生成する |
| FR-11 | P3 | 入力は最終トランスクリプトのみ。パース・統合・要約は純粋な変換に寄せる |
| FR-17 | P2 | 会議サービス由来の WebVTT を直接入力に、Transcribe を経ず最終トランスクリプトと議事録を生成する（`--mode vtt`）。`--no-summarize` で課金ゼロ・完全ローカル。ボイスタグ `<v 名前>` は命名ゲートの初期値に供する |
| FR-18 | P2 | 録画 mp4 から ffmpeg で音声抽出し、Transcribe を経て WebVTT を生成する独立ツール（`subtext-mp4-to-vtt`）。出力は FR-17 経路へ接続する |

### ライブ字幕

| コード | 優先度 | 内容 |
|--------|--------|------|
| FR-12 | P2 | Transcribe Streaming（ja-JP）で、自分・相手のラベル付き即時字幕を出す |
| FR-13 | P3 | 表示は最小限（コンソール）でよい |
| FR-14 | P3 | ライブ字幕の遅延と暫定結果（partial）の安定性を検証できる |

### 構成・連携

| コード | 優先度 | 内容 |
|--------|--------|------|
| FR-15 | P2 | C# 側・Python 側がそれぞれ設定（リージョン・モデル・入力デバイス・サンプルレート）を持つ |
| FR-16 | P2 | ユニット間の連携点は、保存ファイル（WAV・最終トランスクリプト JSON）と会議サービス由来の WebVTT に限定する。共有設定・共有ライブラリを持たない |

追加機能の要件コード（FR-A1-xx、FR-B1-xx、FR-B1F-xx、FR-C1-xx、FR-C2-xx、FR-H2-xx）は第 5 節にまとめる。

## 2. 非機能要件（NFR）

### 全般

| コード | 内容 |
|--------|------|
| NFR-01 | 成果物は CLI／スクリプト。GUI は作り込まない |
| NFR-02 | 想定会議規模は相手最大 5 名（話者分離が精度を出す 2〜5 名の範囲） |
| NFR-03 | 言語構成を分割する。音声経路は C#（.NET、NAudio）、会議後処理は Python |
| NFR-04 | 音声キャプチャ層はネイティブ Windows で動かす（WSL 内に置かない） |
| NFR-05 | Python はプロジェクトローカルに閉じ、グローバル環境を汚さない。当初 3.11／3.12、現行 3.13 |
| NFR-06 | 依存は C#＝NAudio ＋ AWS SDK for .NET、Python＝boto3。VAD は持たず無音分割は Transcribe に委ねる |
| NFR-07 | AWS リージョンは東京（ap-northeast-1）。Bedrock Claude を使う |
| NFR-10 | 型注釈を付け、エラーは握りつぶさず意味のあるメッセージで処理する |
| NFR-11 | モジュールは機能境界で分割し、IO・状態を持つ層と純粋変換層を分ける |

### セキュリティ（NFR-SEC）

Security Baseline を適用する（ゲートにはしない。Q7=A、データ保護観点に限定）。

| コード | 内容 |
|--------|------|
| NFR-SEC-01 | 会議音声を置く S3 は保存時暗号化を有効化し、転送は TLS で行う |
| NFR-SEC-02 | IAM は Transcribe・Bedrock・対象 S3 に限定する。ワイルドカード権限を避ける |
| NFR-SEC-03 | S3 はパブリックアクセスを遮断する。設定・IaC にデフォルト認証情報を置かない |
| NFR-SEC-04 | ログに会議音声内容・話者名（PII）・認証情報を出力しない |
| NFR-SEC-05 | 依存はロックファイル／正確なバージョンで固定する。公式レジストリのみを使う |
| NFR-SEC-06 | 外部呼び出し（AWS API・ファイル IO）に明示的なエラーハンドリングを行い、エラー時は安全側に倒す |
| NFR-SEC-07 | AWS 認証情報をソースコードに直書きしない（環境変数・プロファイル・SSO） |

CLI の個人利用のため、ロードバランサ・Web エンドポイント・多ユーザー認証・監視基盤に関わる SECURITY 系項目は非該当とした。
Resiliency Baseline（Q8=B）と Property-Based Testing（Q9=C）は適用しない。

## 3. 業務ルール（BR）

### Unit A：録音（C#）

| コード | 内容 |
|--------|------|
| BR-DEV-01 | self は capture 方向、others は render 方向のデバイスでなければならない |
| BR-DEV-02 | 名前指定があれば完全一致するデバイスが存在しなければならない（曖昧回避のためエラー） |
| BR-DEV-03 | 名前指定が無ければ当該方向の既定デバイスを採る |
| BR-DEV-04 | 起動時に採用デバイス名と「既定／指定」の別をコンソール表示する |
| BR-FMT-01 | 永続化する全 WAV は 16000Hz / mono / 16bit PCM でなければならない |
| BR-FMT-02 | 正規化順序はダウンミックス → リサンプル → 量子化に固定する |
| BR-FMT-03 | 量子化時のオーバーフローは飽和（クリップ）で処理する。ラップアラウンド禁止 |
| BR-FMT-04 | 正規化は新フレームを返し、入力を変更しない |
| BR-SYNC-01 | 各フレームの絶対時刻は `captureUtc` を唯一の真実とする |
| BR-SYNC-02 | あるべき位置を `captureUtc` から算出し、正のギャップは無音補填、負のギャップは連続書込で吸収する |
| BR-SYNC-03 | 無音補填の発火閾値 `GAP_THRESHOLD` を定数化する（既定 20ms＝320 サンプル） |
| BR-SYNC-04 | 両系統 WAV は先頭サンプルを t0 とし、サンプル index で時間整合する |
| BR-SYNC-05 | 補填した無音を系統ごとに `silenceFilledSec` へ累積記録する |
| BR-QLT-01 | 混入除去のコード処理は実装しない（スコープ外・運用で抑制） |
| BR-QLT-02 | `silenceFilledSec` と録音長をメタに残し、混入・欠落を主観確認できるようにする |
| BR-QLT-03 | 相手系統が全区間無音の場合は警告する |
| BR-IO-01 | sessionId は `yyyyMMdd-HHmmss`。出力先が既存なら衝突エラー（上書き防止） |
| BR-IO-02 | 出力固定名は `self.wav`／`others.wav`／`*.meta.json`／`manifest.json`（連携契約） |
| BR-IO-03 | manifest.streams は self と others のちょうど 2 件 |
| BR-IO-04 | 連携はファイル経由のみ。プロセス間直接連携や DB 共有を持たない |
| BR-STOP-01 | 手動停止（Ctrl+C）でいつでも正常終了できる（主停止手段） |
| BR-STOP-02 | 経過時間が最大録音時間に達したら自動的に正常停止する（既定 180 分） |
| BR-STOP-03 | 正常停止時は残バッファを書き切り WAV ヘッダを確定する |
| BR-ERR-01 | 録音中の致命的異常は fail-fast で停止する |
| BR-ERR-02 | 異常停止でも書込済みをフラッシュし WAV ヘッダを確定する（部分保存） |
| BR-ERR-03 | 異常時は `manifest.status=incomplete` を記録する |
| BR-ERR-04 | エラーメッセージに秘密情報・認証情報・フルパスを含めない |
| BR-ERR-05 | エラーは握りつぶさず、原因の分かるメッセージとともに非ゼロ終了する |
| BR-SEC-01 | 認証情報・秘密をコードや設定に直書きしない |
| BR-SEC-02 | 録音音声・メタはローカルにのみ保存し、外部送信しない |
| BR-SEC-03 | ログに音声内容・PII を出力しない |
| BR-SEC-04 | NuGet 依存はバージョン固定 |

### Unit B：会議後パイプライン（Python）

| コード | 内容 |
|--------|------|
| BR-IN-01 | 入力は 3 モード（`paired`／`single`／`vtt`）。それ以外は起動エラー |
| BR-IN-02 | `single` は others 系統のみ処理し、self 統合・絶対時刻統合をしない。入力 WAV の内容ハッシュを`input_media.sha256` に残して照合し、同名の別音声で前回成果物を再利用しない |
| BR-IN-03 | `paired` で `status=incomplete` でも停止せず続行し、議事録冒頭に部分録音の注記を付す |
| BR-IN-04 | 入力 WAV は 16kHz/mono/16bit PCM であること。不一致はエラー（再正規化しない） |
| BR-IN-05 | 連携点は WAV・meta・会議サービス由来 WebVTT のみ。Unit A の内部実装に依存しない |
| BR-IN-06 | `vtt` モードは WebVTT を純粋変換で最終トランスクリプトに生成する。話者は出現順 `spk_n`、ボイスタグは命名ゲートの初期値ヒントに保持する |
| BR-IN-07 | ボイスタグが機械ラベル（`^spk_\d+$`）なら実名ヒントにしない（記入待ちのまま揃える） |
| BR-JOB-01 | self は話者分離なし（単一話者 `self`）、others のみ `ShowSpeakerLabels=true` |
| BR-JOB-02 | others の最大話者数は設定値（既定 5） |
| BR-JOB-03 | 言語は `ja-JP`（設定で上書き可） |
| BR-JOB-04 | jobName は衝突しない一意名。再実行で名前衝突しない |
| BR-JOB-05 | 完了はポーリング（指数バックオフと上限）で待つ。タイムアウト・FAILED は失敗として送出する |
| BR-PARSE-01 | 出力粒度は発言セグメント単位。単語タイムスタンプは保持しない。語の連結は言語で決める（`ja`/`zh`/`yue` は区切りなし、それ以外は空白。句読点は直前の語へ密着させる） |
| BR-PARSE-02 | セグメントの confidence は内包 item の平均（取得不能時は None） |
| BR-PARSE-03 | others は話者境界でセグメント分割、self は無音・休止で分割し話者 `self` 固定 |
| BR-MERGE-01 | self と others を録音開始共通基準の `startSec` 昇順でマージする |
| BR-MERGE-02 | `commonStartUtc` があれば各セグメントに絶対時刻を付ける（single・欠落時は None） |
| BR-MERGE-03 | マージは純粋変換（外部状態を読まない）。同入力→同出力 |
| BR-MERGE-04 | 最終トランスクリプトは連携契約。JSON は camelCase・enum 文字列で Unit A 出力と整合 |
| BR-NAME-01 | 実名割当はファイル方式。未存在時はテンプレートを生成し merged 段で停止する（非対話） |
| BR-NAME-02 | ファイル存在時に適用。未記入ラベルは元の `spk_n` のまま維持し `unresolved` に列挙する |
| BR-NAME-03 | 声紋等の自動命名は行わない。実名は人手入力のみ |
| BR-NAME-04 | 実名（PII）をログ出力しない。マッピングファイルはローカルのみで S3 へ送らない |
| BR-SUM-01 | 必須セクションは「決定事項」「ToDo（担当・期限・完了条件）」「論点・議論サマリ」「未決事項」「要確認箇所」の5つ、この順序。日本語 Markdown |
| BR-SUM-02 | 入力は最終トランスクリプトのみ。会議外データ・外部状態を参照しない |
| BR-SUM-03 | 決定事項の各行には時刻を必須併記する。他セクションは可能な範囲で発言者・時刻を出典併記する |
| BR-SUM-04 | 使用モデル ID・リージョンは設定由来。使用モデルを `minutes.meta.json` の `sourceModel` に残す |
| BR-SUM-05 | 部分録音由来なら冒頭に注記する |
| BR-SUM-06 | 議事録生成は 2 系統（Bedrock 生成／`--no-summarize` で外部生成）。後者は PII が Anthropic へ送信される。見出しと出力先 `minutes.md` は共通 |
| BR-SUM-07 | 文体・フォーマットを統一する。常体で書き、一文一項目・一文は短く言い切る。発言の要約は間接話法にし一人称・敬語を残さない。冗長な言い回しや「活発な議論が行われた」等の空句、予告・総括だけの空文（「重要なのは〜である」）、空虚な形容・動詞（「多角的に」「掘り下げる」）、根拠のない弱い緩和（「〜と言えるだろう」）を避ける。ただし「など」「かもしれない」は発言者自身の表現であれば保持する（落とすと網羅・断定の創作になる）。同じ文をそのまま別セクションへ再掲しない（決定に至る経緯を論点サマリで述べるのは重複ではない）。別々の決定・原因を一つの言葉でくくらない。箇条書き記号は `- ` に統一し、入れ子は付帯情報（ToDo の担当・期限・完了条件、決定事項の前提・却下・範囲、未決事項の要・影響）の1段のみ許す。論点見出しは作業名ではなく何についての論点かを名詞句で特定し、目安3〜6行（水増し・切り捨てはしない）。`## ` 見出しの追加禁止は5セクションに対する規則で、`# {会議名}`・`### {論点名}` は対象外。書く内容が無いセクションは省略せず「特になし」と明記する。ToDo 項目間・セクション間には空行を1行入れる |
| BR-SUM-08 | 創作禁止を徹底する。却下案・前提・範囲はトランスクリプトで述べられている場合にかぎり併記する。聞き取り不能・意味不明箇所は本文に `[要確認]` と記し、**本文に残したまま**「要確認箇所」セクションへ一覧として集約する（本文からの移動ではない）。専門用語の明らかな誤変換は修正のうえ原文を併記する（資料を根拠にした場合も括弧は1つにまとめる）。声紋・口調・自己紹介からの話者名推定は行わない（`BR-NAME-03` を維持、話者ラベルはそのまま用いる）。発言者の立場変更があった場合は変更後の内容とともにその旨を残す |
| BR-SUM-09 | 議事録の先頭に会議名（トランスクリプトに明示がある場合のみ）・日時・参加者のヘッダーを書く。日時・参加者は FinalTranscript（セッションID・話者一覧等）から決定的に算出した値をそのまま転記し、推測しない |
| BR-MI-01 | `meeting_info.json`（人手記入・任意）の項目単位で BR-SUM-09 の決定的算出を上書きする。全項目未記入なら現行の算出のまま。会議名は記入があるときのみ `[システム情報]` に現れる。記入をスキップした場合も空のファイルを残す（「訊いた」ことの記録。CLI と TUI で挙動を揃える） |
| BR-EDIT-01 | `minutes.md` が手編集済み（`minutes.meta.json` の `edited: true`）のとき、自動トリガーによる要約段の再実行はこれを上書きしない。`--force` または `--target-stage summarize` の明示指定のときのみ上書きし、`edited` フラグをリセットする |
| BR-MAT-01 | 付帯資料は固有名詞・略語・論点名の表記是正・補完にのみ用いる。資料にしか無い事実・数値・予定は議事録の記述根拠にしない。資料由来の補完には出典（ファイル名）を付記する。**数値は資料で書き換えない**（是正できるのは同一の値の表記揺れのみ。値が食い違う場合は発言を優先し、判断できなければ `[要確認]` を付ける） |
| BR-PIPE-01 | 各段は中間成果物ファイルが存在すればスキップする（再利用）。内容の妥当性は検証しない |
| BR-PIPE-02 | `--force` で全段再実行。段指定の再実行を許す |
| BR-PIPE-03 | 中間成果物はローカル出力先に保存する |
| BR-PIPE-04 | Transcribe 段の再実行は明示時のみ（意図しない再課金を避ける） |
| BR-PIPE-05 | `--no-summarize` は要約段と C2 補正段を実行せず `final_transcript.json` 生成後に正常終了する。`--stage summarized`・`--stage corrected` とは併用不可 |
| BR-IO-01 | S3 は保存時暗号化・パブリックアクセス遮断を前提とする。満たさなければ安全側に停止する |
| BR-IO-02 | ジョブ成功後、`keepS3=false`（既定）なら入力・結果を削除する。`--keep-s3` で保持 |

### A1：ライブ字幕の再接続耐性

| コード | 内容 |
|--------|------|
| FR-A1-01 | 例外を一過性（transient）と致命（fatal）に分類し、transient なら自動再接続する |
| FR-A1-02 | 再接続は系統ごとに独立して行う。他系統を巻き込まない |
| FR-A1-03 | 再接続の待機は指数バックオフで行う |
| FR-A1-05 | keep-alive 間隔を超えて capture フレームが届かなければ無音 PCM を注入し、Transcribe の 15 秒 idle timeout を起こさない |
| FR-A1-06 | 再接続時に当該系統の表示状態をリセットする。オフセットは新しいストリーミングセッションの 0 起点に戻る。境界マーカー行で混線を明示し、final の重複除去は行わない |
| FR-A1-07 | 全系統が終了（恒久障害または停止要求）するまで稼働を続ける |
| FR-A1-08 | 再接続の発生をログに残す。字幕テキスト・認証情報・例外メッセージは載せない |

| FR-MAT-04 | 抽出テキストの総文字数に上限（既定 `MATERIALS_MAX_TOTAL_CHARS=40000`）を設け、超過分はファイル単位で末尾から除外する |
| FR-MAT-05 | `--no-materials` で無効化できる（抽出も FR-MAT-06 の再実行トリガーも行わない） |
| FR-MAT-06 | `materials/` の内容が前回抽出時と一致しないとき、要約段のみを再実行対象にする（`minutes.md` が既にあり、かつ付帯資料が有効な場合に限る） |
| FR-MAT-07 | 抽出は非課金・ローカル処理のため `--no-summarize`（Claude 生成経路）でも実行し、`materials.extracted.json` を残す（Claude はこのファイルを読んで議事録を書く） |

不変条件（BR-MAT-01：用途の限定・出典付記・資料を記述根拠にしない）は Unit B の表（第 3 節）にある。
画像（.png 等）・スキャン PDF の vision 抽出は対象外（将来対応）。

## 6. 検証スパイクと実機課題（SC-Pn / ISS-nn）
