# インフラ設計

Unit B が使う AWS インフラを定義する。
インフラは AWS CDK（Python）でコード化し、`infra/` 配下に置く。
リージョンは東京（ap-northeast-1）を既定とする（NFR-07）。
実装では `CDK_DEFAULT_REGION` 未設定時の既定値であり、同変数で上書きできる（運用では東京に固定する）。

`infra` は依存が重いため uv workspace には含めず、デプロイ時のみ `infra/` 配下で個別に `uv sync` する。

## S3

処理用に PoC 専用のバケットを 1 つ持つ（Q1=A）。
名前は明示せず CDK の自動生成に委ねる（推測困難でグローバル一意な名前が得られるため）。
実際の名前はスタック出力から `.env` へ転記する。
オブジェクトのプレフィックスは、入力音声を `subtext/jobs/<sessionId>/`、出力を `subtext/jobs/<sessionId>/transcribe/` に置く。
入力音声は録音経路では WAV、mp4→VTT 経路では ffmpeg で抽出した FLAC（`audio.flac`）である。
カスタム語彙（C1）の用語ファイルだけは別系統で、`subtext/vocab/<語彙名>.txt` に置く。

セキュリティ設定は次のとおりである。

- **保存時暗号化**：SSE-S3（AES256、S3 管理キー）。鍵管理は不要（Q2=A、NFR-SEC-01）。
- **パブリックアクセス遮断**：Block Public Access の 4 項目をすべて有効化する（NFR-SEC-03）。
- **TLS 強制**：バケットポリシーで `aws:SecureTransport=false` を拒否する（NFR-SEC-01）。
- **ライフサイクル**：全オブジェクトを 7 日で失効させる。アプリは成功後に即削除するため、これは削除漏れや失敗残骸に対する保険である。未完了のマルチパートアップロードは 1 日で中止する。
- **バージョニング**：無効にする（機微データの滞留を避ける）。
- **撤去**：スタック削除時にバケットを中身ごと削除する（PoC のため。本番運用では保持を検討する）。この指定により CDK が削除用の Lambda と IAM ロールを追加生成する。

## IAM

PoC 専用の主体を 1 つ置き、リソース ARN を限定してワイルドカード権限を避ける（Q4=A、NFR-SEC-02）。

| 用途 | アクション | リソース |
|------|-----------|----------|
| S3 の入出力と後始末 | `s3:PutObject` / `GetObject` / `DeleteObject` / `ListBucket` / `GetEncryptionConfiguration` / `GetBucketPublicAccessBlock` | 対象バケットの ARN |
| Transcribe（ジョブ） | `transcribe:StartTranscriptionJob` / `GetTranscriptionJob` / `ListTranscriptionJobs` | `*`（条件なし） |
| Transcribe（カスタム語彙） | `transcribe:CreateVocabulary` / `UpdateVocabulary` / `GetVocabulary` | `*`（条件なし） |
| Bedrock | `bedrock:InvokeModel` | 指定モデルの推論 ARN（リージョン・モデル ID 限定） |

Transcribe は ARN レベルの絞り込みが限定的なため、条件を付けずに `*` を許容する。
広域権限を `Deny` で相殺する設計は採らない（過剰防御を避ける）。
Transcribe の 2 行だけは最小権限を貫けていない点を、明示的な残存リスクとして扱う。
語彙側は ARN で絞れるかを一次情報で確認できていないため、ジョブ側と同じく `*` に倒している（確信度：中）。
実デプロイでは、使用モデルが推論プロファイル経由でしか呼べないため、IAM を「プロファイル ARN と ap-northeast-1／3 の foundation-model ARN」へ拡張し、最小権限を保つ。

## Transcribe と Bedrock

Transcribe はジョブ実行型で、プロビジョニングを要さない（IaC の対象外）。
バッチは self / others を別ジョブで実行し、others のみ話者分離（最大 5）を有効化する。
言語は `ja-JP` である。

Bedrock は要約に使う（BR-SUM）。
モデル ID は `.env` と設定で外出しし、コードに直書きしない（Q5=A）。
呼び出しは `bedrock-runtime`（boto3）で行い、使用モデルを `minutes.meta.json` の `sourceModel` に残す（BR-SUM-04）。
モデルアクセスの有効化は IaC 化が難しいため、手動手順とする。

実デプロイで確定したモデルは `jp.anthropic.claude-opus-4-8`（推論プロファイル、`ap-northeast-1`／`ap-northeast-3` へのルーティング）である。
新しめの Claude はオンデマンドでは呼べず、推論プロファイル経由のみである。

モデル選定はデータ所在の制約が先に立つ。
`jp.` プロファイルを持つモデルに限る、という条件で選んでいる。
2026-07-29 時点で Sonnet 5 には `jp.` プロファイルが存在せず、`global.anthropic.claude-sonnet-5`（全対応リージョンへルーティング）しか用意されていないため採らなかった。
より新しいモデルへ上げる際も同じ順序で判断する。
すなわち `jp.` プロファイルの有無を先に確認し、無ければそのモデルは候補から外す。

モデルを変えるときは、`infra/stacks/subtext_poc_stack.py` の既定値と foundation-model 名、`.env` の `BEDROCK_MODEL_ID`、そして会議ハーネスの `meeting.toml` の `[pricing.bedrock]` を揃えて更新する。

## CDK スタック

スタックは `SubtextPocStack`（`stacks/subtext_poc_stack.py`）である。
主要リソースは、上記の S3 バケット、最小権限の IAM 主体、および出力（CfnOutput）である。
これに加えて、バケットの中身ごと削除する指定に伴う削除用 Lambda と IAM ロールが CDK によって生成される。
出力にバケット名・IAM 主体名・Bedrock モデル ID を載せ、`.env` へ転記する。
Bedrock のモデル ID は CDK context キー `bedrockModelId` で上書きできる。
全リソースに共通タグ（`Project`・`Component`・`Environment`・`ManagedBy`・`Owner`）を付ける。
依存（`aws-cdk-lib` など）はロックファイルで固定する。

## デプロイ手順

1. 前提（手動・一度きり）：東京リージョンの利用確認、Bedrock での Claude モデルアクセス有効化、ローカル認証情報の準備（直書き禁止）。
2. IaC：`infra/` を uv でセットアップし、`cdk bootstrap`（未実施のみ）、`cdk deploy`、出力の控え。
3. `.env` 設定：`AWS_REGION=ap-northeast-1`、`S3_BUCKET=<CDK 出力>`、`BEDROCK_MODEL_ID=<有効化済み>`。任意で `AWS_PROFILE`（使うプロファイル。未指定なら SDK 既定）・`S3_PREFIX`・`LANGUAGE`・`MAX_SPEAKERS`・`POLL_TIMEOUT_SEC`・`KEEP_S3`・`OUTPUT_DIR`・`VOCABULARY_NAME`（C1）・`CORRECTION_TERMS_PATH`（C2）。Slack へ投稿する場合は `SLACK_BOT_TOKEN` も置く。雛形は `.env.example` にある。
4. 疎通確認。撤去は `cdk destroy`。

## 既知の運用上の注意

- CDK CLI はグローバル導入せず、`infra/package.json` の `devDependencies` にバージョン固定で置く（NFR-SEC-05）。`npx` 経由で実行する。
- カスタム語彙（C1）の投入ツールは Transcribe の語彙操作に加えて、用語ファイルを `subtext/vocab/` へ置くための S3 書き込みを要する。いずれも上記の IAM 主体に含めてある。
- 最小権限ユーザーはアクセスキーを未発行のままで、現状の疎通は実行者の権限で動いている（ISS-08）。最小権限ユーザー単体での検証は別途とする。
