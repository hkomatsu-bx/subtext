# Unit B：会議後パイプライン

Unit B は、録音または字幕を入力に、文字起こし・話者分離・統合・実名割当・要約を経て議事録を生成する。
言語は Python 3.13 である。
文字起こしと要約に Amazon Transcribe と Amazon Bedrock を使い、AWS 課金が発生する。

## 責務と設計原則

Unit B の中核は「データを受け取り結果を返す純粋な変換」に寄せる（FR-11）。
特にパース段と統合段は外部状態を読まず、同じ入力からは同じ出力を返す（BR-MERGE-03）。
AWS API やファイル IO を持つ段（アップロード・Transcribe・要約）は、純粋変換段と分けて配置する。

型注釈を付け、エラーは握りつぶさず、意味のあるメッセージとともに処理する（NFR-10）。

## 3 つの入力モード

入力は 3 モードあり、いずれか 1 つで起動する（BR-IN-01）。

- **paired**：Unit A のセッションディレクトリ（`manifest.json`）を入力に、self と others の 2 系統を処理する。主経路。`manifest.streams` に self と others の両方が揃っていることを要求し、片系統でも欠ければ停止する（Unit A の BR-IO-03）。
- **single**：単一 WAV を入力に others 系統のみ処理する（Q7=A）。話者分離の品質検証（SC-P2）に用いる先行検証用モード。self の統合と絶対時刻統合は行わない（BR-IN-02）。
- **vtt**：WebVTT を入力に、Transcribe と S3 を経ずに最終トランスクリプトを直接生成する（FR-17）。

paired で `manifest.status=incomplete` の場合、処理は止めずに続行し、最終議事録の冒頭に部分録音の注記を付す（BR-IN-03、BR-SUM-05）。
入力 WAV は Unit A が正規化した 16kHz / mono / 16bit PCM であることを前提とし、不一致はエラーにする（BR-IN-04、再正規化はしない＝責務分離）。

WebVTT 経路では、話者を出現順の安定ラベル `spk_n` に割り当てる（BR-IN-06）。
ボイスタグ `<v 名前>` は命名ゲートの初期値のヒントとして保持する。
ただしボイスタグが機械ラベル（`^spk_\d+$`）の場合はヒントにせず、記入待ちのまま Transcribe 経路と揃える（BR-IN-07）。
ボイスタグを持たないキューは、すべて 1 つのラベル（`spk_0`）へ集約する。

本文と話者名の文字実体参照（`&amp;` `&lt;` `&gt;` 等）は復元する。
WebVTT は本文の `&` と `<` をエスケープする仕様であり（`vtt_writer` も同じ変換を掛ける）、
復元しないと `A&B` が `A&amp;B` のまま `final_transcript.json` → 議事録 → Slack へ流れて恒久的に壊れる。
復元はタグ除去の**後**に行う（先に戻すと本文の `&lt;` が `<` になり、その先がタグとみなされて本文の一部が消える）。

WebVTT 経路の細部を 3 点補う。
セッション ID は入力ファイル名の拡張子を除いた部分を使う。
全話者の `origin` は `others` に固定し、`confidence` と絶対時刻は持たない（元データに無いため）。
統合段の成果物も書き出すので、命名ゲートで停止したあとの再実行では変換をやり直さない。

セッション ID がファイル名由来である帰結として、**同名の別ファイルは同じ出力ディレクトリを共有する**。
Teams 既定の `Recording.vtt` やライブ字幕由来の `live_captions.vtt` は毎回同名になるため、
段の再利用がこれを「続きから」と解釈すると前の会議の実名入り議事録を成功として返し、今回の内容はどこにも書かれない。
そこで既存の統合成果物があるときは入力の指紋（セグメントの時刻・話者ラベル・本文のハッシュ）を照合し、別入力なら続行せずリネームを促して停止する。

## 段の構成

オーケストレータ `PostMeetingPipeline` が次の段を駆動する。
各段の完了は成果物ファイルの有無だけで判定し、中間成果物があればその段をスキップする（BR-PIPE-01、Q4=A）。
中身の妥当性は検証しない。
読み込みに失敗した時点で初めて `PipelineError` になる。
`--force` で全段を再実行し、段を指定した再実行（例：要約のみ）も許す（BR-PIPE-02）。
Transcribe 段の再実行は明示時（`--force` または成果物欠落）に限り、意図しない再課金を避ける（BR-PIPE-04）。

段の判定に使う成果物のファイル名は固定である。

| ファイル | 段 |
|----------|----|
| `raw_transcribe.self.json`／`raw_transcribe.others.json` | Transcribe 結果の生データ |
| `final_transcript.merged.json` | 統合まで完了 |
| `final_transcript.named.json` | 実名割当まで完了（C2 補正の入力・補正前の原文） |
| `final_transcript.json` | 最終トランスクリプト（C2 有効時は補正後） |
| `speaker_names.json` | 話者名マッピング（人手編集） |
| `meeting_info.json` | 会議名・日時・参加者（人手編集・任意、FR-MI-01） |
| `minutes.md`／`minutes.meta.json` | 議事録と生成メタ（`minutes.meta.json` の `edited` は②議事録編集が立てる） |
| `minutes.generated.md` | ②議事録編集が初回編集時に退避する生成直後の版（会議ハーネスの `edit.py` が書く） |
| `materials/` | 付帯資料の投入先（③付帯資料。会議ハーネスの `meeting materials` が置く） |
| `materials.extracted.json` | 付帯資料の抽出結果キャッシュ（③付帯資料。内容ハッシュで差分検知） |

段は次の順に並ぶ。

0. **認証事前チェック**：課金段に入る前に STS で資格情報の有効性を確認する（BR-H2-AUTH-02）。
1. **入力解決**：モード判定と入力検証。
2. **S3 アップロード**：正規化済み WAV を保存時暗号化・パブリックアクセス遮断のバケットへ置く（NFR-SEC-01／03）。
3. **Transcribe 実行**：self と others を別ジョブで文字起こしする（Q1=A）。others のみ話者分離（`ShowSpeakerLabels`、最大話者数は設定値・既定 5）を有効化し、self は単一話者 `self` に固定する（BR-JOB-01／02）。言語は既定 `ja-JP` で、環境変数 `LANGUAGE` で上書きできる（BR-JOB-03）。`VOCABULARY_NAME` が設定されていればカスタム語彙を付与する（C1、FR-C1-02）。完了はポーリング（5 秒から 30 秒への指数バックオフ、上限は `POLL_TIMEOUT_SEC`・既定 1800 秒）で待ち、タイムアウトや FAILED は失敗として送出する（BR-JOB-05）。
4. **結果パース**：発言セグメント単位に正規化する。単語タイムスタンプは保持しない（BR-PARSE-01、Q5=A）。confidence は内包 item の平均とする（BR-PARSE-02）。純粋変換。
5. **統合**：self と others のセグメントを録音開始（0）共通基準の `startSec` 昇順でマージする（BR-MERGE-01）。paired で `commonStartUtc` があれば各セグメントに絶対時刻を付ける（BR-MERGE-02、Q2=A）。純粋変換。
6. **実名割当**：ファイル方式（Q3=A）。マッピングファイルが無ければテンプレートを生成し、統合後の段で停止する（[話者名ゲート](#話者名ゲート)）。あれば適用する。
7. **補正（C2、任意）**：LLM と決定的辞書で固有名詞の表記を是正する。詳細は [08-追加機能.md](08-追加機能.md) を参照する。
8. **要約**：Bedrock（Claude）で議事録を生成する。
9. **永続化・後始末**：成果物を保存し、`keepS3=false`（既定）なら S3 のオブジェクトを削除する（BR-IO-02）。

S3 の掃除は成功時だけではない。
完走・命名ゲートでの停止・例外による失敗のいずれの終了経路でも、当該セッションのプレフィックス配下を冪等に削除する（BR-H2-S3-01）。
ローカルの中間成果物は再実行のために保全するが、S3 側は残さない。

### コマンドライン引数

| 引数 | 用途 |
|------|------|
| `--mode {paired,single,vtt}` | 入力モード（`--check-auth` 以外では必須） |
| `--session <dir>` | paired のセッションディレクトリ |
| `--vtt <file>` | vtt モードの入力ファイル |
| `--stage {transcribed,merged,named,corrected,summarized}` | 指定段を強制再実行する |
| `--force` | 全段を再実行する |
| `--no-summarize` | 要約段と C2 補正段をスキップする |
| `--no-correct` | C2 補正段のみスキップする |
| `--keep-s3` | 成功後も S3 のオブジェクトを残す |
| `--env-file <file>` | 読み込む `.env` を指定する |
| `--profile <name>` | 使う AWS プロファイル（省略時は環境変数 → `.env` → SDK 既定） |
| `--check-auth` | 資格情報の疎通確認だけを行い、パイプラインを実行しない |
| `--verbose` | 詳細ログを出す |

矛盾する組み合わせは課金前に拒否する。
`--no-summarize` と `--stage summarized`、`--no-correct`／`--no-summarize` と `--stage corrected` が対象である。

### AWS プロファイルの選択

どのプロファイルで AWS を呼ぶかは次の順で決める。

```
--profile  >  環境変数 AWS_PROFILE  >  .env の AWS_PROFILE  >  未設定（SDK 既定＝default プロファイル）
```

決まった値はエントリポイントで**環境変数 `AWS_PROFILE` へ 1 回書き出す**（`aws.apply_profile`）。
boto3 クライアント生成は `aws.build_client` と `auth_check` の 2 か所だが、その先の呼び出し元は 4 か所あり、`S3Io`／`TranscribeClient` のコンストラクタ（`region` しか受けていない）まで引数が波及する。
プロファイル選択はプロセス全体の設定なので、境界で 1 回だけ環境へ渡す方が影響が小さく、後から増えるクライアントも自動的に従う。

**未指定のときは `AWS_PROFILE` を設定しない。**
`default` を明示的に入れてはならない。
botocore はプロファイルが明示されていると、`~/.aws/config` に該当セクションが無い場合 `ProfileNotFound` を送出する（未設定なら空の設定を返して許容する）。
`[default]` を持たない環境（資格情報を環境変数で渡す運用や CI）で、今まで動いていたものが壊れる。
表示上は `Session().profile_name` が未設定時に `default` を返すため、操作者には `default` と見える。

プロファイル名は資格情報ではなく「どのプロファイルを使うか」の指定であり、`.env` に置いても NFR-SEC-07 に反しない。

### 資格情報の疎通確認（`--check-auth`）

段 0 の認証事前チェックだけを単体で実行する経路である（課金なし）。
`--mode` を取らず、S3 バケットの必須検証も外す（認証確認に S3 は要らない）。

これは呼び出し側のためにある。
段 0 は「課金段に入る直前」に走るため、資格情報が切れていることは**議事録生成を押した後**にしか分からない。
会議ハーネスはこれを起動時に呼び、録音を始める前に失効を知らせる（FR-H2-11）。

結果は機械可読な 1 行として stdout へ出す（Unit A の `sessionId=` と同方針）。

```
authProfile=default
authRegion=ap-northeast-1
authStatus=ok
```

`authStatus` は `ok` と、`auth_policy` の分類（`expired` / `forbidden` / `profile_not_found` / `transient` / `unknown`）を取る。
`profile_not_found` は指定プロファイルが `~/.aws/config` に無い場合で、再ログインでは解決しないため期限切れと分けている（`--profile` の綴り違いで起こる）。
`ok` 以外では終了コードを非ゼロにし、続く行に対処メッセージ（`remediation_message`）を出す。

**アカウント ID・ARN・ユーザー名は出さない**（BR-H2-AUTH-04）。
`GetCallerIdentity` は呼ぶが、応答からは成否だけを使う。
呼び出し側がこの出力を画面やログへ流す前提なので、身元情報を載せると BR-ERR-04・NFR-SEC-04 の範囲がそこまで広がる。
profile 名と region は環境設定であり秘密ではないため、操作者が「どの口座に向いているか」を確かめられるように出す。

分類・リトライ・対処メッセージは段 0 と同じ `auth_policy` を使う（実装も同じ probe を共有する）。
確認の経路が 2 つに増えても、判定と文言の正本は 1 つに保つ。

## 話者名ゲート

話者名ゲートは、「`spk_0` は誰の発言か」を人間が確定するまで議事録を作らせない安全弁である（BR-NAME-01）。

初回実行は統合後に `speaker_names.json` のテンプレート（各話者ラベルと代表発言サンプル、self は「自分」）を生成し、`NAMING_REQUIRED` で停止する。
ユーザーがラベルへ実名または役割を記入して再実行すると、マッピングを適用して先へ進む。
未記入のラベルは元の `spk_n` のまま維持し、未解決として列挙する（BR-NAME-02）。

VTT 経路では話者名（`model_info["speakerNameHints"]`）をテンプレートの初期値に入れるが、**自動補完したラベルは `_hintedLabels` に記録する**。
ヒントは実名とは限らず、ライブ字幕由来なら Unit C の表示ラベル「自分」「相手」、Teams なら「Speaker 1」のような仮名になる。
値が入っていることを「人が確認済み」と解釈すると、下流（会議ハーネスの命名ゲート）が素通りして仮名のまま議事録ができるため、確認済みかどうかを値の有無とは別に持つ。
`_hintedLabels` は `_clusters` と同じ補助情報で、Unit B 自身は読み戻さない（`SpeakerNameMap.from_json` は未知キーを無視する）。

`speaker_names.json` を直して再実行すれば訂正は反映される。
`final_transcript.named.json` の再利用は、マッピングファイルの更新時刻が `named` より新しいときに無効化する（命名以降を作り直し、下流の補正・要約も連鎖して再実行される）。
これが無いと、成果物の存在だけを見た再利用によって訂正が黙って無視され、古い名前のまま「完了」と報告されてしまう（会議ハーネスは `--force` も `--stage` も渡さないため、他に訂正手段が無い）。

声紋などによる自動命名は行わない（BR-NAME-03、スコープ外）。
実名（PII）はログに出さず、マッピングファイルはローカルのみに置き S3 へ送らない（BR-NAME-04、NFR-SEC-04）。

話者名の割り当てを Claude Code に手伝わせる場合、Claude が実名入りトランスクリプトを読むため、PII が Anthropic 側へ送信される。
PII を社外に出さない運用では、話者名は手作業で記入する。

## 要約バックエンド

議事録の文章化は 2 系統から選ぶ（BR-SUM-06）。
どちらを使うかは情報の取り扱い方針で決める。

- **Bedrock 生成（既定）**：パイプラインが `minutes.md` まで生成する。文字起こしも要約も自社 AWS 内に留まる。要約は日本リージョン内に閉じる推論プロファイル経由のため、所在は `ap-northeast-1` と `ap-northeast-3` のいずれかである（[07-インフラ設計.md](07-インフラ設計.md) を参照）。
- **Claude 生成（`--no-summarize`）**：要約段をスキップし `final_transcript.json` で停止する（BR-PIPE-05、`SUMMARIZE_SKIPPED`）。Bedrock を呼ばないため課金は発生しない。文章化は Claude Code が担う。この経路は実名入りトランスクリプトが Anthropic 側へ送信される点が Bedrock 経路と決定的に異なる。

`--no-summarize` を指定すると、要約段だけでなく C2 用語補正段も自動でスキップする（BR-PIPE-05）。
これにより WebVTT 経路と `--no-summarize` の組み合わせは AWS 課金ゼロになる。

ただしこれは、Claude 生成経路を常用すると用語補正が一度も効かないことを意味する。
固有名詞の表記は補正されないまま Claude へ渡るため、表記を揃える責任は Claude 側のプロンプトに移る。
詳細は [08-追加機能.md](08-追加機能.md) の C2 節を参照する。

どちらの経路でも議事録の見出しは統一する（BR-SUM-01）。
必須セクションは「決定事項」「ToDo（担当・期限・完了条件）」「論点・議論サマリ」「未決事項」「要確認箇所」の5つで、この順序・日本語 Markdown で出力する。
入力は最終トランスクリプトのみで、会議外データや外部状態は参照しない（BR-SUM-02）。
トランスクリプトに無い情報は創作しない。
決定事項の各行には時刻を必須で併記する。他セクションは可能な範囲での出典併記でよい（BR-SUM-03）。

文体・フォーマットも両経路で統一する（BR-SUM-07）。常体・一文一項目で書き、間接話法（一人称・敬語を残さない）にし、冗長な言い回しや実質的な情報を含まない定型句を避ける。箇条書き記号は `- ` に統一する。書く内容が無いセクションは省略せず「特になし」と明記する。
重複の禁止は「同じ文をそのまま別セクションへ再掲しない」ことに限る。決定に至る経緯を論点・議論サマリで述べることは重複に当たらない（決定事項は結論、論点サマリは議論の流れを持つ）。射程を「一つの決定は一度だけ」に広げると、論点サマリが決定に触れられなくなり「決定と事実報告には発言者を付けない」という同セクションの規則と衝突する。
別々の決定・原因を一つの言葉でくくらず腑分けすることも求める。
論点見出しは作業名（「検討」「対応」）ではなく、何についての論点かを名詞句で特定する。行数は目安として3〜6行とし、満たすための水増しも収めるための切り捨ても禁じる。
禁止する定型句には、状況描写・感情推測・書き手の評価に加え、予告・総括だけの空文（「重要なのは〜である」「まとめると」）、空虚な形容・動詞（「多角的に」「掘り下げる」）、根拠のない弱い緩和（「〜と言えるだろう」）を含める（`japanese-tech-writing` の LLM 口調禁止のうち議事録に転用できる部分を取り込んだもの）。
ただし「など」「かもしれない」は、**発言者自身がその表現を使った場合は保持させる**。落とすと列挙が網羅である・断定であるかのような創作になるため、禁じるのは書き手が曖昧にする用法に限る。
付帯情報（ToDo の担当・期限・完了条件、決定事項の前提・却下・範囲、未決事項の要・影響）は1行に詰め込まず、親の行の下に1段インデントした箇条書きにする（1行だと見落とされるため）。入れ子はこの用途に限り、深さも1段に限る。ToDo 項目間・セクション間には空行を1行入れる。
`## ` 見出しの追加禁止は5セクションに対する規則であり、1行目の `# {会議名}` と論点ごとの `### {論点名}` は対象外である。

創作禁止はさらに具体化する（BR-SUM-08）。却下案・前提・範囲はトランスクリプトで述べられている場合にかぎり併記し、聞き取り不能・意味不明箇所は本文に `[要確認]` と記す。「要確認箇所」セクションへの集約は**本文にマーカーを残したうえでの一覧化**であり、本文からの移動ではない（移動と解釈されると本文のどこが不明だったのか追えなくなる）。専門用語の明らかな誤変換は修正のうえ原文を併記する（Claude 経路で C2 補正が走らない分を、要約プロンプト側の責任として明文化したもの）。
**声紋・口調・自己紹介の発言からの話者名推定は行わない。** 話者ラベル（`spk_0` 等）はそのまま用いる。実名の確定は `BR-NAME-03` が定める話者名ゲート（人手入力のみ）に一本化し、要約プロンプト側で代替経路を作らない。

議事録の先頭には、5セクションより前に会議名・日時・参加者のヘッダーを置く（BR-SUM-09）。日時と参加者は
FinalTranscript から決定的に算出できる値（セッションID由来の日時、話者一覧）であり、モデルには算出済みの
値を転記させるだけにして推測させない。会議名はデータとして持たないため、トランスクリプトの発言中に会議
そのものの名称が明示されている場合にかぎりモデルが書き、無ければ省く。

`meeting_info.json`（人手記入・任意、FR-MI-01）が存在し、かつ全項目が空でなければ、その値を
`[システム情報]` へ差し込んで上記の決定的算出を上書きする（BR-MI-01）。項目単位で上書きし、
未記入の項目だけ現行の算出値を使う。会議名は算出値を持たないため、`meeting_info.json` に記入が
あるときだけ `[システム情報]` に会議名の行が現れ、モデルはその値をそのまま `# {会議名}` に転記する
（発言中の明示を推測する経路とは別に、記入があれば優先する）。
記入は話者名ゲート（`NAMING_REQUIRED`）と同じ停止点で行う（`tools/meeting` のウィザード／TUI）。
`meeting_info.json` が `minutes.md` より新しいときは要約段のみを再実行対象にする。命名・補正段には
影響しない（Bedrock 再課金を伴うため、呼び出し側で額を提示してから実行する）。

`minutes.md` が手編集済み（`minutes.meta.json` の `edited: true`。②議事録編集）のときは、
この自動再実行を止める。`--force` または `--target-stage summarize` の明示指定が無い限り
`PipelineError` を送出し、手編集した内容を自動トリガーで黒く上書きしない（BR-EDIT-01）。
明示指定で上書きした場合は新しい生成物で確定し、`edited` フラグはリセットされる。

付帯資料（③・FR-MAT）は `materials/` に投入されたファイルを Unit B が抽出し、`[参考資料]` として
要約プロンプトへ渡す。対応形式は `.txt`／`.md`／`.pdf`（`pypdf` のテキスト層のみ）／`.pptx`
（`python-pptx` のスライドテキストと発表者ノート）。画像とスキャン PDF は対象外（将来対応）。
抽出は内容ハッシュでキャッシュし、変更のあったファイルのみ再抽出する。総文字数の上限
（既定 4 万文字）を超える分はファイル単位で末尾から除外する。用途は固有名詞・略語・論点名の
表記是正・補完に限定し、資料にしか無い事実は議事録の記述根拠にしない（出典付記を求める）。

**数値は資料で書き換えさせない。** 是正できるのは同一の値の表記揺れに限り、資料と発言で値が
食い違う場合は発言の値を採用させる（判断できない場合は発言の値を書いて `[要確認]` を付ける）。
会議で資料と違う数字が合意されるのは通常の事態であり、資料へ寄せる余地を残すと合意内容そのものが
失われる。用途の列挙から「数値」を外しているのはこのためである。
`materials/` の内容が変わったときも、`minutes.md` が既にあれば要約段のみを再実行対象にする
（meeting_info.json と同じ仕組み）。`--no-materials` で無効化できる。C2 補正段には資料を渡さない
（補正は構造不変が要件のため）。

## エラー処理

AWS API とファイル IO の例外は握りつぶさず、文脈付きの `PipelineError` として送出する（BR-ERR-01、Q9=A）。
失敗時は安全側に停止し、生成済みの中間成果物は保全して再実行で再利用できるようにする（BR-ERR-02）。
終了コードは非ゼロにし、どの段で失敗したかを明示する（BR-ERR-03）。
例外メッセージとログに、音声内容・実名（PII）・AWS 認証情報を含めない（BR-ERR-04、NFR-SEC-04）。

非ゼロになるのは失敗した場合だけである。
話者名の記入待ちで止まる `NAMING_REQUIRED` と、要約段をスキップして止まる `SUMMARIZE_SKIPPED` は設計どおりの中断であり、終了コードは 0 になる。
呼び出し側（会議ハーネスや Claude Code）は終了コードではなく、この停止理由を見て次手順を決める。

## 派生ツール：mp4 → VTT 変換

録画 mp4 から WebVTT を作る独立ツール `subtext-mp4-to-vtt` を同じパッケージに持つ（FR-18）。
ffmpeg で音声を 16kHz / mono FLAC に抽出してから Transcribe（話者分離）にかけ、`<v spk_0>` 書式の WebVTT を出力する（BR-VTT-01／02）。
Teams の動画 mp4 は Transcribe が直接 parse できない（"Failed to parse audio file"）ため、抽出を挟む。
出力 VTT はそのまま `vtt` モードへ渡せる。
既定の出力先は入力と同じ場所の `.vtt` で、`--out` で変えられる。
音声トラックを持たない mp4 は、原因の分かる形で停止する（BR-VTT-01）。

S3 のキーは `<prefix><セッションID>/audio.flac` と `<prefix><セッションID>/transcribe/others.json` である。
抽出音声と S3 オブジェクトは、成功・失敗いずれの経路でも破棄する（BR-VTT-03）。
課金の主体は Transcribe だが、S3 のリクエストと一時保管の料金も厳密には発生する。
本体と同じく、課金段の前に資格情報の有効性を確認する。
前提として ffmpeg が PATH 上にあること。

## 派生ツール：ライブ字幕 JSONL → VTT 変換

B1F（ライブ字幕の永続化基盤）が出力する確定字幕の JSONL を WebVTT へ変換する独立 CLI `subtext-live-to-vtt` を同じパッケージに持つ（FR-B1F-05）。
既定の出力先は入力と同じ場所の `.vtt` で、`--out` で変えられる。
追記中の未完行や破損行は捨てて処理を続ける（BR-B1F-IO-01）。
cue の並びと開始時刻は `captureUtc` を正とする（BR-B1F-TIME-01）。
AWS を一切使わないため、この変換自体に課金はない。
出力 VTT はそのまま `vtt` モードへ渡せる。
詳細は [08-追加機能.md](08-追加機能.md) の B1F 節を参照する。
