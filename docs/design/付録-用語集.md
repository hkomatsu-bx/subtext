# 付録：用語集

本設計書で使う用語を定義する。

**セッション**：1 回の会議に対応する作業単位。`data/recordings/<yyyyMMdd-HHmmss>/` のように日時が識別子（sessionId）になる。

**ユニット**：責務・言語・外部依存で分けた実装の単位。Unit A（録音）・Unit B（会議後パイプライン）・Unit C（ライブ字幕）の 3 つがある。

**連携契約**：ユニット境界を越えて受け渡すファイルの形式の取り決め（FR-16）。共有ライブラリや共有設定を持たず、ファイルだけで連携する。

**WASAPI**：Windows Audio Session API。OS の音声層。Subtext はこれで、システム出力（相手の声）をループバック取得し、マイク（自分の声）を別系統で取得する。

**ループバック**：スピーカーへ出力される音声を入力として取得する経路。相手の声の取得に使う。無音時にデータを出さないことがあり、同期の補正を要する。

**self / others**：録音の 2 系統。self はマイク（自分の声）、others はループバック（相手の声）。

**正規化**：capture が既定形式（多くは 48kHz・浮動小数点）で取得した音声を、recorder が 16kHz・モノラル・16bit PCM に変換すること。Transcribe のストリーミングとバッチの双方に適合する形にする。

**captureUtc**：各音声フレームに付く取得時刻。2 系統の同期の唯一の真実として使う（BR-SYNC-01）。

**話者分離（ダイアライゼーション）**：文字起こしの発言を話者ごとのクラスタ（`spk_0` など）に分ける処理。Amazon Transcribe のバッチ（`ShowSpeakerLabels`）で行う。日本語での品質が PoC 最大の不確実性だった（FR-08）。

**話者名ゲート**：「`spk_0` は誰の発言か」を人間が確定するまで議事録を作らせない安全弁（BR-NAME-01）。どの入力経路でも必ず 1 回停止する。

**最終トランスクリプト（final_transcript.json）**：話者ラベル付きで統合されたトランスクリプト。要約段の入力であり、外部（Claude Code）へ渡すこともできる連携契約（FR-16）。C2 の補正を有効にしている場合は補正後で確定し、補正前の実名済みテキストは `final_transcript.named.json` に残る（BR-CORR-04）。

**paired / single / vtt**：Unit B の 3 つの入力モード（BR-IN-01）。paired は録音成果物、single は単一 WAV 検証、vtt は WebVTT。

**WebVTT**：字幕ファイル形式。`vtt` モードの入口になり、`<v 話者名>` のボイスタグを持つ。会議サービス（Teams 等）が出力したものに加え、録画 mp4 とライブ字幕 JSONL からも変換して作れる。

**subtext-mp4-to-vtt**：録画 mp4 から ffmpeg で音声を抽出し、Transcribe を経て WebVTT を生成する独立 CLI（FR-18）。同じパッケージの第 2 CLI。

**subtext-live-to-vtt**：Unit C が永続化したライブ字幕 JSONL を WebVTT へ変換する独立 CLI（FR-B1F-05）。同じパッケージの第 3 CLI。cue の並びは `captureUtc` を正とする。

**fail-fast**：異常を検知したら握りつぶさず、安全側に停止して非ゼロ終了する方針。Unit A と Unit B のエラー方針である。Unit C は当初これに倣っていたが、A1 が系統ごとの自動再接続と生存系統の継続へ反転させた。

**会議ハーネス（meeting）**：録音から議事録・Slack 投稿までを 1 か所から駆動するオーケストレータ。CLI と TUI を持つ。

**コスト台帳（cost-ledger.jsonl）**：課金を伴う実行の概算を追記で記録するファイル。閾値超過で警告する。金額は概算で、正は AWS Cost Explorer とする。

**Bedrock 経路 / Claude 生成経路**：議事録の文章化の 2 系統（BR-SUM-06）。Bedrock 経路は自社 AWS 内に留まる。Claude 生成経路（`--no-summarize`）は実名入りトランスクリプトが Anthropic 側へ送信される。

**トレーサビリティコード**：`FR-xx`（機能要件）・`NFR-xx`／`NFR-SEC-xx`（非機能要件）・`BR-xxx-xx`（業務ルール）・`Qn=X`（設計判断）。追加機能スライスではスライス名を挟んだ `FR-A1-xx`・`NFR-C2-xx`・`BR-H2-AUTH-xx` の形も使い、設計判断の細目 `DG-<スライス>-n` と受け入れ条件 `AC-<スライス>-nn` が加わる。ソースコードのコメントから設計意図を引くための識別子で、定義は [付録-トレーサビリティ.md](付録-トレーサビリティ.md) にある。検証スパイク `SC-Pn` と実機課題 `ISS-nn` は作業記録側の識別子で、付録は扱わない。
